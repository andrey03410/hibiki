# Реализация личной выдачи и загрузки треков

Основание — [продукт](product.md) и [технические решения](tech.md). Порядок работы для каждого изменения — воспроизвести недостающее поведение тестом, реализовать, проверить профильные сценарии. Сохраняем обычный потоковый запуск и приватность аналитики.

- [x] Сервер и контракт. В `library-pages.ts` добавить браузерные сортировки `popular`, `recent`, `random`, seed и общий идентификатор снимка для страницы и очереди. Устранить повторный поиск для счётчиков. Проверить пересечение с тегами, стабильность страниц и изоляцию аккаунтов.
- [x] Медиатека. В существующем селекторе предоставить новые режимы и компактное повторное перемешивание. Подключить один снимок к выдаче и очереди. Поиск при вводе задержать на 150 мс и отменять устаревшие запросы. Проверить возврат, узкий экран и пустой результат.
- [x] Загрузка аудио. Для активного собственного аудиофайла организовать быструю выдачу первых байтов и догрузку до конца с ограниченной памятью. Использовать общий буфер для начала одного следующего трека, корректно учитывать смену очереди, источник и права.
- [x] Шкала. Показать только запас от текущей позиции в обеих панелях и обновлять его после перемотки или смены вкладки. Проверить разрыв, неизвестную длительность и смену источника.
- [x] Приёмка. Запустить полную тройку проверок, сравнить поиск на одном тестовом наборе до/после, реальный первый звук и переход на быстрой и ограниченной сети. Проверить интерфейс и сеть браузера, провести независимое ревью.
- [x] Выпуск. Обновить карточки зон и историю по фактическому результату, открыть и влить PR, дождаться production workflow, проверить HTTPS, активный релиз и worker.
