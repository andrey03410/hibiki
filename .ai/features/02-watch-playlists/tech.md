# Техника

Решения агента в автономном режиме. Проверены library.ts, jobs.ts, youtube.ts,
player.tsx, карточки media/web/youtube. Стек и БД сохраняются.

## Исходная система

PlayerProvider уже держит единую очередь и native/YouTube-движки над маршрутами,
но видео плавающее, очередь выдвижная. В SourceDto уже есть thumbnail. Локальный
анализ пропускает обложки. YouTube discovery получает полный flat playlist
без скачивания; job сохраняет позиции и id items, но теряет название коллекции.

## Решения

- T01. Встроить постоянную watch-поверхность в layout: видео 16:9 и очередь
  рядом, единый engine сохраняется. Fullscreen охватывает сцену с controls.
  Пауза через UI и клавиатуру; обработчик игнорирует поля ввода.
- T02. Для локального audio отдавать owner-scoped artwork по авторизованному
  endpoint, извлекать встроенную обложку из оригинала, ограничивать тип/размер.
  Сгенерированная обложка не требует миграции или отдельной копии в архиве:
  восстанавливается из переносимого оригинала. Fallback при отсутствии обложки.
- T03. Реальные операции через существующий MCP/REST и jobs. До удаления демо —
  полный export. Только восемь известных items владельца, без прямого SQL удаления.
  Импорт двух playlist URLs, проверка результатов и повторов, пакетные теги,
  source sort + manualOrder исходных позиций. Не создавать youtube-download jobs.
- T04. Сохранить исходное название коллекции в отчёте задания импорта и явно
  показывать недоступные позиции. Ошибки внешнего провайдера не выдавать за
  успешный полный импорт. Три Key OST — import-local из allowlist.
- T05. Изолированные задачи frontend/artwork можно вести параллельными агентами
  с отдельными файлами; root ведёт реальные данные и интеграцию. Перед merge
  свежий независимый reviewer и весь QG.

## Документация и проверка

[YouTube IFrame API](https://developers.google.com/youtube/iframe_api_reference)
проверена 17.11.2026: видимый iframe, события состояния/ошибки, play/pause,
viewport не менее 200×200. [music-metadata](https://github.com/Borewit/music-metadata)
поддерживает embedded artwork; используются установленные типы пакета.

Карточки: web, media, youtube/jobs при изменении отчёта. Проверки: тесты нового
поведения, обязательная тройка, реальный MCP, оба реальных плейлиста и повтор,
браузер агента с декодированным YouTube/audio, artwork, fullscreen, паузой,
смешанными переходами и сохранением engine между страницами. Изоляция artwork
от другого пользователя и перенос аудио с обложкой.
