# Техника

T01. Флаг KANAME_ENABLED=1 включает проверку назначения из Kaname на сервере. Authorization Code Flow проверяет PKCE, state, подпись ID token, issuer, audience и nonce. Одноразовое состояние привязано к HttpOnly-cookie. Локальные сессии помечаются способом входа.

T02. Аддитивная SQLite-миграция связывает User.id с issuer/subject и хранит локальную приостановку и суточную активность. Учётные данные портала и службы отчётов разделены. Сервер и worker проверяют центральные права. Запись медиа ограничивается общей квотой в SQLite при конкурентной обработке.

T03. Обновляются карты медиа, MCP, заданий и архитектуры. Проверки выполняются в отдельном SQLite-хранилище, затем на живом HTTP и в браузере. Промышленная привязка, контрольное восстановление и проверка SHA выполняются при координированной выкладке.

## Включение на существующей установке

1. Согласовать issuer, public subject, confidential client hibiki, точный callback и S256 с Kaname. Передать значения из .env.example в API и worker. KANAME_OWNER_SUBJECT задаёт заранее проверенный public subject владельца.
2. До миграции и привязки снять согласованную копию SQLite и каталога storage с медиа. Восстановить копию в изолированный каталог и проверить SQLite integrity_check, внешние ключи, исходный User.id, число записей, плейлистов, файлов и их чтение. Промышленную приёмку и резервное копирование выполняет координатор выкладки.
3. Выполнить npm run db:deploy. Узнать существующие локальные id чтением User.id, login. Сверить subject в Keycloak с центральным назначением площадки. Для каждого существующего аккаунта выполнить `npm run kaname:bind -- EXISTING_USER_ID VERIFIED_SUBJECT`. Команда проверяет ответ Kaname, соответствие логина и неизменность ранее установленной связи. Для andrey обязательны закреплённый KANAME_OWNER_SUBJECT и роль overlord. В таблице User она меняет только поля связи. Для ранее созданных архивов и загруженных замен она учитывает размер имеющихся на диске файлов в новой таблице квот. Для новых участников без конфликтующего локального логина профиль создаёт первый OIDC-вход.
4. Установить KANAME_ENABLED=1 одновременно для API и worker. Получить новый личный MCP-токен в настройках. Проверить вход, User.id, выдачу, плейлисты, HTTP Range и воспроизведение сопоставлением с восстановленной копией. Для отключения интеграции флаг снимают у обоих процессов. Данные и поля связи при этом сохраняются.

Обычные авторизованные обращения идут в /internal/v1/access/:subject с KANAME_SERVICE_TOKEN. Секрет KANAME_REPORT_TOKEN используется только для входящего отчёта. Срок окна входа пять минут. Окно хранится в памяти единственного web-процесса и сбрасывается при его перезапуске. Реестр медиа использует размер файлов по подтверждённому импорту. Работающие операции держат краткоживущие квотные резервы. Квитанции на архивы и загруженные замены сохраняются при публикации. Тяжёлая конвертация требует роли overlord и разрешения heavy.
