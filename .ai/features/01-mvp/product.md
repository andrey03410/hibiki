# Продуктовые решения

**Статус:** предложение первой итерации. Название, ПК и ограничение текущей работы
документами подтверждены владельцем. Остальная детальная семантика — рекомендация
агента на основе исходного брифа; продуктовый гейт ещё не пройден.

## Цель

Пользователь собирает личную медиатеку и описывает желаемые подборки агенту.
Hibiki хранит библиотеку независимо от доступности внешних ссылок, вычисляет
плейлисты по правилам и даёт удобное воспроизведение на ПК.

## Решения

### P01. Название и платформа

- Варианты названия: Otoha, Tsunagi, Neiro, Hibiki, Otoniwa.
- **Решение владельца:** Hibiki; ПК и браузер. Телефон не нужен для MVP.

### P02. Пул и источники

- Требование владельца: личный пул каждого пользователя; файлы и YouTube-ссылки.
- Варианты: отдельная запись для каждого источника; один item с несколькими источниками.
- Рекомендация: постоянный `MediaItem` с источниками YouTube и/или локальным файлом.
  Скачивание добавляет локальный источник к тому же item. Теги и плейлисты сохраняются.
- **Решение:** предложено агентом; ожидает подтверждения.

### P03. Названия и недоступность

- Требование владельца: item и название остаются после удаления или скрытия видео.
- Рекомендация: отдельно хранить собственное название и сохранённое название источника.
  По умолчанию название заполняется метаданными, без выдумывания агентом.
  Синхронизация источника не затирает собственные правки.
- Ошибка сети не равна удалению. Недоступность относится к источнику, а не к item.
  Ролик с доступом по ссылке сам по себе не считается удалённым.
- Если видео недоступно ещё до первого импорта, прежнее название может быть неизвестно.
- **Решение:** сохранение требуется владельцем; детали предложены агентом.

### P04. Импорт YouTube-плейлиста

- Требование владельца: одно обращение к агенту добавляет каждое видео отдельным item.
- Варианты: снимок состава; постоянная синхронизация с YouTube.
- Рекомендация MVP: разовый импорт публичного или доступного по ссылке плейлиста.
  Повторный импорт добавляет новые items, узнаёт существующие и не удаляет пул.
  Недоступные обнаруженные позиции сохраняются с известными ID и метаданными.
- Задание показывает добавленные, существующие, недоступные позиции и ошибки.
  Один проблемный ролик не отменяет успешный импорт остальных.
- **Решение:** массовый импорт требуется владельцем; режим снимка предложен агентом.

### P05. Теги

- Требование владельца: предустановленные и пользовательские теги, по запросу.
- Рекомендация: редактируемые теги в медиатеке пользователя с устойчивыми ID;
  начальный набор создаётся при создании аккаунта. Агент видит каталог и может
  создать свой тег. Автоматически размечать всё без запроса не нужно.
- **Решение:** требование владельца; организация каталога предложена агентом.

### P06. Плейлисты

- Требование владельца: другие плейлисты, теги, ручные добавления и исключения;
  изменения вложенных подборок автоматически меняют состав результата.
- Варианты: отдельные типы списков; единая модель правил.
- Рекомендация: единая модель с объединением, пересечением, разностью и фильтрами
  по тегам, типу медиа, локальной доступности и длительности. Обычный список —
  ручные items. Фильтры можно сочетать, состав отделён от порядка.
- Дубликаты одного item убираются; исключения побеждают добавления. Циклы запрещены.
  Порядок: ручной у обычного списка, стабильный по источникам либо явная сортировка
  у составного. Каждый результат можно объяснить происхождением.
- Сайт даёт редактор правил и предпросмотр, MCP — ту же схему и объяснение.
- **Решение:** составность и UI требуются владельцем; семантика предложена агентом.

### P07. Плеер и сворачивание браузера

- Требование владельца: удобный плеер и shuffle; ПК, без телефона.
- Рекомендация: постоянный плеер между страницами; play/pause, перемотка, громкость,
  следующая/предыдущая позиция, очередь, shuffle без повторов до конца прохода,
  повтор трека/очереди, сохранение очереди и позиции после перезагрузки.
- Локальный готовый источник приоритетен. Недоступный item остаётся в библиотеке,
  в очереди его можно пропустить с объяснением.
- Динамический состав актуален при открытии/обновлении; уже запущенная очередь —
  снимок, чтобы правки плейлиста не переставляли текущий трек.
- **Решение владельца:** сворачивание сделать сейчас, если реализуемо без блокера.
  В реализации проверить локальное audio/video в свёрнутом браузере. Для YouTube
  учитывать поведение и правила встроенного плеера; скрытый iframe не использовать
  как способ гарантировать фоновый звук. Записать фактический результат проверки.
  Сон компьютера и выгрузка вкладки не являются обещанным фоновым воспроизведением.
- Остальная семантика плеера предложена агентом.

### P08. Агент и сайт

- Требование владельца: агент — основной путь добавления, но нужен и UI.
- Рекомендация: полноценные операции доступны обоим клиентам; общий сервис проверяет
  владельца. У MCP есть описание возможностей, пакетные изменения, проверка,
  предпросмотр/объяснение плейлистов и управление фоновыми заданиями.
- Внешний агент подключается личным токеном. Встроенный чат с LLM не нужен.
- **Решение:** направление владельца; конкретный контракт предложен агентом.

### P09. Переносимость

- Требование владельца: сохранить настройки и медиа и импортировать на другом ПК
  либо другому пользователю.
- Варианты: копия БД; переносимая библиотека; оба способа для разных задач.
- Рекомендация: экспорт метаданных/ссылок либо полный архив с локальными файлами.
  В него входят items, теги, правила/порядок плейлистов, очередь и настройки плеера.
  Пароли, сессии и MCP-токены не переносятся в пользовательском архиве.
- При импорте сопоставить ID, переназначить владельца и переписать внутренние ссылки.
  Ошибки и совпадения показать до применения; исходную библиотеку не менять.
  Архив без локальных файлов не восстановит удалённое видео по одной ссылке.
- **Решение:** перенос требуется владельцем; формат и поведение предложены агентом.

## Что войдёт в первую итерацию

Все девять сценариев выше, в пределах локального ПК-сервиса: простые аккаунты,
медиатека, YouTube и файлы, скачивание, теги, единый движок плейлистов, плеер,
MCP, задания и перенос. Возможности должны работать сквозным сценарием,
а не оставаться набором отдельных прототипов.

## Не входит

Мобильный клиент, другие внешние сервисы, YouTube OAuth для приватных библиотек,
автосинхронизация состава YouTube-плейлиста, социальные функции, рекомендации,
DSP/эквалайзер/crossfade, PWA-офлайн-кэш, realtime-синхронизация установок.

## Приёмка

1. Импортировать реальный YouTube-плейлист через MCP, повторить без дублей.
2. Добавить локальные audio/video; отредактировать названия и теги через UI и MCP.
3. Объединить «Опенинги» и «Эндинги», добавить тег и item, задать исключения;
   добавить item в исходный список и увидеть изменение составного результата.
4. Получить объяснение состава, проверить запрет циклических зависимостей.
5. Скачать доступный ролик в источник того же item и воспроизвести локально.
6. Воспроизвести очередь с shuffle, перемоткой и восстановлением состояния;
   зафиксировать поведение свёрнутого браузера для каждого вида источника.
7. Проверить недоступный внешний источник без потери item и метаданных.
8. Экспортировать библиотеку и восстановить под другим аккаунтом и в чистой
   установке; проверить файлы, настройки и ссылки составных плейлистов.
9. Проверить изоляцию пользователей и восстановление заданий после перезапуска.
