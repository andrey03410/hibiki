# Независимое ревью первой итерации

Проверена вся реализация относительно main. Ревьюер не менял рабочее дерево или
пользовательскую БД; воспроизведения выполнены в /tmp с изолированным testContext.
База первой волны исправлений: `6761e4a`.

Предварительный QG root перед этой базой: 78 тестов / 11 файлов → build → tsc,
все успешно. Это не финальная готовность: перечисленные замечания исправляются.

## Обязательные исправления

1. `LibraryService.deleteItem`: очистить ссылки manualOrder и сохранённых
   queue/originalQueue с нормализацией текущей позиции. Сохранить защиту явных
   ссылок правила items. Удаление из динамической библиотеки не должно ломать
   resolve/export. setSettings также нормализует обе очереди.
2. `importLocal/store`: после metadata-only import отсутствующий MediaFile нельзя
   переиспользовать как готовый без восстановления байтов. Проверить/восстановить
   файл до публикации available источника, сохранив item/file identity.
3. `upsertYoutube`: повторная проверка owner/provider/videoId и запись атомарны.
   Два одновременных импорта сейчас создают два items и один source.
4. `savePlaylist`: проверка графа и запись атомарны. Одновременные A→B/B→A
   не должны оба проходить и оставлять цикл.
5. Jobs: graceful stop на третьей попытке сейчас оставляет queued attempt=3,
   которое больше не выбирается. Штатный stop не создаёт вечного задания.
6. Upload: отдельный лимит архива, согласованный с переносом до 20 ГиБ.
   Общий лимит обычного media upload 2 ГиБ не должен блокировать большие архивы.

## Небольшое исправление

7. Multipart upload файла без ID3/title сохраняет случайный UUID вместо исходного
   имени. Исходное имя — fallback после встроенных метаданных, безопасный для пути.

## Дополнительная проверка

8. При появлении локальной копии играющего YouTube-item позиция не должна
   сбрасываться на ноль. Проверить source transition и сохранить текущую позицию
   либо удерживать выбранный работающий источник до следующего запуска.

## Процедура

Одна согласованная волна исправлений с регрессионными тестами, затем QG и
ограниченное повторное ревью исправлений тем же независимым ревьюером.
Результат каждого пункта будет дописан после проверки, не по обещанию исправить.

## Что ревьюер не оценивал

Живой браузер, фоновое воспроизведение и финальная тройка проверяются root;
эти проверки не заменяются статическим вердиктом.
