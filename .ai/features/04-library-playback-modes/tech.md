# Технические решения

## Исходная система

`PlayerProvider` живёт над маршрутами и сохраняет очередь, позицию и контекст
плейлистов локально и через настройки аккаунта. Сейчас его сцена выводится над
всеми маршрутами. Поиск медиатеки уже возвращает отсортированный массив записей,
а таблица и страницы плейлистов используют один контроллер воспроизведения.

## T01. Маршрут и воспроизведение

- Оставить один провайдер над маршрутами. Выводить сцену и очередь на `/player`,
  компактную панель на страницах коллекции и на остальных экранах.
- Нативное аудио остаётся смонтированным между маршрутами. Видео и видимый
  YouTube-плеер загружаются только на `/player`. Выход из видео ставит его на паузу,
  сохраняя позицию. Автопереход вне этого маршрута выбирает запись и ждёт «Смотреть».
- При смене источника в пределах записи использовать сохранённую позицию и
  сохранить контекст очереди. Кнопки автопроигрывания, переходов и системные
  медиакнопки учитывают доступность выбранного режима.
- Режим `original | audio` восстанавливается вместе с очередью. Старое сохранённое
  состояние читается как `original`. В обычном режиме приоритет у источника
  соответствующего типа, в звуковом — у доступных локальных звуковых источников.

## T02. Поддержка звукового режима

- Признак звуковой дорожки исходного и подготовленного локального файла следует
  из FFmpeg-проверки, уже используемой при импорте. Сервер передаёт опциональный
  `SourceDto.hasAudio`. Существующие файлы получают результат проверки без
  создания копий и повторного хэширования. Для недоступного файла признак
  остаётся неизвестным. Архив проверяет реальные файлы при импорте.
- Браузер воспроизводит звук совместимого локального контейнера через аудиоэлемент.
  YouTube без локального источника и видео с известным отсутствием звука
  недоступны для этого режима. Очередь сохраняет такие позиции и объясняет пропуск.
- Новая настройка режима валидируется и входит в перенос очереди. Схема архива
  принимает ранее экспортированные настройки.

## T03. Выдача

- Прямой запуск и «Играть найденное» используют ту же выдачу `searchLibrary`.
  Новый запуск выдачи сохраняет весь порядок и выбранный индекс. Действия с
  очередью и деталями записи общие для списка и карточек.
- Выбор представления — настройка браузера для аккаунта. Фильтры используют
  текущую модель поиска, панель дополнительных условий меняет только способ ввода.
  Список и карточки используют одно состояние массового выделения.

Карточки, которые обновляются по результату: [сайт](../../map/web.md),
[медиа](../../map/media.md), [перенос](../../map/portability.md).
Живая проверка — во встроенном браузере с локальным аудио и видео, смешанной
очередью, реальной ссылкой YouTube и изоляцией двух проверочных аккаунтов.

Решения приняты в рамках автономного режима задачи.
