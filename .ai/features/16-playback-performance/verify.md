# Проверка задачи 16

## Исходная версия

Сборка `b148eb0`, Chrome и WebKit, вход через Kaname. Временная вкладка
перехватывает запись настроек и истории. Для сравнения использованы одни
и те же исходные файлы. Скрипт, исходные и итоговые данные находятся вне Git
в `storage/verification/16-playback-performance/`.

| Проверка исходной версии | Результат |
|---|---:|
| Запуски в Chrome, 5 типов файлов | по 20 |
| Старт MP3 с большой ID3, p50 / p95 | 1681 / 5049 мс |
| Неизменившаяся сводка | HTTP 200, 241 678 байт |
| Фоновые ответы API за 10 минут, Chrome | 47 284 886 байт |
| Записи localStorage за тот же интервал | 2381 |
| Первая загрузка JS, CSS, сводки и страницы | 1 035 635 байт |
| Те же ресурсы после изменения Caddy | 285 287 байт |

Размеры сети взяты из Resource Timing. Для фонового сценария отдельно учитываются
музыка и перехваченные попытки записи. Первое открытие измеряется после очистки
кеша временного браузера.

## Проверки реализации

- Перед работами сверены содержимое 2 970 файлов с SHA-256 и контрольные суммы
  карточек, правил плейлистов, связей тегов, настроек и истории.
- Живой клиент MCP в изолированной установке получил импортированную карточку.
  Второй аккаунт прочитал Range общей виртуальной дорожки до отзыва ссылки.
  При повторном обращении после отзыва сервер вернул 404.
- При полном ZIP-переносе в другой аккаунт совпали хеш оригинала, хеш виртуальной
  дорожки и порядок записей в плейлисте. В архив вошёл один исходный медиафайл.
- В локальных Chrome и WebKit проверены декодирование, перемотка, офлайн-буфер,
  граница предзагрузки, прокрутка очереди из 2 668 записей, обрыв JSON во время
  воспроизведения и редактирование плейлиста.
- В пробной загрузке YouTube звуковые пакеты исходного WebM, полученного Ogg
  и дорожки видеоверсии MP4 дали одинаковый SHA-256.
