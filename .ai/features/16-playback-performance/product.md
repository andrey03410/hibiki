# Продуктовые решения для обсуждения

Все решения ниже — предложения агента. Решения владельца ещё не получены.

## Цель

Трек из медиатеки начинает звучать почти сразу. Текущий трек загружается целиком,
после этого готовится начало одного следующего. В звуковом режиме не скачивается
видео. Поиск, плейлисты и редактор не заставляют ждать, а фоновые запросы
не отнимают сеть у музыки. Качество звука не меняется: никакого перекодирования
и сжатия треков.

## Как проверяли

Прод 25 ноября 2026, версия `b148eb0`, аккаунт andrey: 2 668 записей, 2 970 файлов,
20 ГБ медиа. Замеры во встроенном браузере с перехватом записи истории и очереди.
Серверное время снято внутри контейнера на копии БД (копия удалена).
Временный плейлист создан и удалён. Очередь, позиция и история после проверки
совпадают с исходными.

Встроенный браузер добавляет ~175–210 мс к каждому запросу. С этой машины RTT
до сервера 38 мс, пропускная способность 50–65 Мбит/с. Поэтому абсолютные
времена из браузера завышены. Важны соотношения и серверное время.

Проверено и в порядке: в звуковом режиме нет элемента `<video>` и YouTube-плеера.
Сервер отвечает быстро: HEAD к файлу 6 мс, блок 1 МиБ 34 мс, первая страница
выдачи 126 мс, текстовый поиск 66 мс, выбор тегов ~150 мс. Сборка полного каталога
не блокирует отдачу файлов. Длинных задач в браузере во время прослушивания нет.

## Сценарии и целевые показатели

Цели для домашней сети (RTT ~40 мс). p50 / p95 по серии из 20 запусков.

| Сценарий | Сейчас | Цель |
|---|---|---|
| Клик по аудиотреку → звук | 0,45 с, с большой ID3 1,85 с (браузер с задержкой) | ≤ 0,3 / 0,6 с для любого своего трека, включая видео в звуковом режиме |
| Конец трека → начало следующего | 0,21 с | ≤ 0,1 с при готовом начале |
| Текущий трек загружен целиком | Только файлы ≤ 32 МиБ | Любой свой трек; для видеозаписи — её звук |
| Трафик за трек у видеозаписи в звуковом режиме | Весь MP4, до 205 МБ | ≈ размер звуковой дорожки |
| Фоновый трафик во время прослушивания | ~4,7 МБ/мин | ≤ 50 КБ/мин без активных заданий |
| Ввод в поиск → карточки | ~0,66 с (браузер с задержкой) | ≤ 0,4 с |
| Открыть редактор плейлиста | 5,6 с | ≤ 1 с |
| Первое открытие медиатеки | overview 236 КБ + страница 198 КБ + JS 476 КБ | Объём передачи в 4 раза меньше, сборка из кеша |

## Решения

### P01. Что значит «трек загружен целиком»

- Варианты: (а) как сейчас — только файлы до 32 МиБ; (б) любой собственный трек,
  у видеозаписи — её звуковая дорожка; (в) любой файл целиком, включая видео
  в видеорежиме.
- Рекомендация: (б). После старта все байты звука текущего трека загружаются
  в память вкладки. После этого можно отключить сеть и дослушать до конца.
  Полоса загрузки показывает фактически загруженное. У загруженного трека
  она заполнена до конца. В видеорежиме оставить нативную потоковую загрузку:
  видео до 205 МБ целиком в память браузера не нужно.
- **Решение:** ждёт владельца.

### P02. Небольшая предзагрузка следующего

- Варианты: (а) как сейчас — около 5 с по среднему битрейту при запасе 5 с у текущего;
  (б) начинать только после полной загрузки текущего, грузить заголовок файла
  и ~10 с настоящего звука; (в) после текущего загружать следующий целиком.
- Рекомендация: (б). Ровно одна следующая запись, которую очередь действительно
  сыграет. Потолок — 2 МиБ. При смене очереди, перемешивании или «Играть следующей»
  устаревшая подготовка отменяется. Готовое начало используется сразу, без
  дополнительной проверки перед стартом (см. P06).
- **Решение:** ждёт владельца.

### P03. Видео в звуковом режиме

- Варианты: (а) играть MP4 целиком, как сейчас; (б) автоматически создать
  звуковую копию видеозаписи без перекодирования: дорожка копируется побайтно,
  битрейт, частота и каналы не меняются; (в) скачивать звук с YouTube заново.
- Рекомендация: (б). Звуковой режим берёт копию, видеорежим — оригинал.
  Запись остаётся одной, теги и связи не меняются. Копию можно удалить и создать
  заново. В экспорт её не включать. Для 280 видеозаписей (~15 ч) нужно
  1–2,6 ГБ. Сейчас на сервере свободно 5,7 ГБ из 59 (занято 90%).
- Открытые вопросы владельцу: учитывать ли копии в квоте Kaname; создать копии
  сразу для всех или при первом прослушивании (первый запуск тогда будет
  обычным потоком).
- **Решение:** ждёт владельца.

### P04. Когда обновлять данные интерфейса в фоне

- Варианты: (а) как сейчас — полная сводка каждые 3 с; (б) опрашивать только
  изменения: при неизменной медиатеке ответ почти пустой, при открытой вкладке.
  Ход заданий — пока задания идут. При возврате на вкладку — сразу.
- Рекомендация: (б). Изменения с другого устройства или от MCP-агента появляются
  в пределах 10 с и мгновенно при возврате на вкладку.
- **Решение:** ждёт владельца.

### P05. Редактор плейлиста

- Рекомендация: открывать форму сразу. Выбор записей и правила ищут по страницам,
  как медиатека. Список тегов берётся из уже загруженной сводки. Предпросмотр
  считается независимо. После создания страница плейлиста не загружается дважды.
- **Решение:** ждёт владельца.

### P06. Проверка доступа к подготовленному треку

Сейчас перед стартом подготовленного файла отправляется отдельный запрос
проверки прав. Это нужно для отозванных ссылок и сессий.

- Варианты: (а) оставить последовательную проверку (+1 RTT на каждый переход);
  (б) проверять параллельно со стартом: при отказе воспроизведение останавливается
  через ~1 RTT, то есть может прозвучать доля секунды уже загруженного звука;
  (в) проверять только для чужих и общих записей.
- Рекомендация: (в) для своих файлов, (б) для общих. Свои файлы на этой вкладке
  уже скачаны под той же сессией.
- **Решение:** ждёт владельца.

### P07. Обложки

- Рекомендация: миниатюры и крупные обложки создаются один раз и хранятся
  на диске рядом с медиа (килобайты на запись). Браузер не перезапрашивает
  неизменённую обложку. Исходные изображения не меняются.
- **Решение:** ждёт владельца.

### P08. Сбой сети

- Рекомендация: обрыв или ошибка фонового запроса не роняет сайт.
  Показывается прежнее состояние и ненавязчивое сообщение. Плеер продолжает
  играть загруженное.
- **Решение:** ждёт владельца.

## Не входит

- Любое перекодирование, понижение битрейта, частоты, разрядности или числа
  каналов треков. Сжатие треков. HTTP-сжатие применяется только к JSON,
  JS и CSS, файлы `/files/*` не сжимаются.
- Переезд на другой сервер, CDN, Redis и отдельные сервисы.
- Ускорение YouTube IFrame: загрузкой там управляет YouTube.
- Изменение состава данных, тегов и плейлистов.

## Приёмка

1. Клик по своему треку, в том числе по видеозаписи в звуковом режиме → звук
   в целевое время. Видеодорожка в сети не скачивается.
2. После полной загрузки полоса заполнена. Сеть отключена → трек дослушивается.
3. Начало следующего запрашивается только после полной загрузки текущего
   и не больше 2 МиБ. Переход к нему ≤ 0,1 с.
4. MP3 с большой обложкой и M4A с индексом в конце стартуют так же быстро,
   как обычные.
5. За 10 минут прослушивания без заданий фоновый трафик ≤ 0,5 МБ.
6. Редактор плейлиста открывается ≤ 1 с и не скачивает весь каталог.
7. Обрыв сети во время прослушивания не даёт белого экрана.
8. Байты звука в браузере совпадают с исходным файлом или его дорожкой (SHA-256).
