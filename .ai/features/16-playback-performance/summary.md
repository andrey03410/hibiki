# Кратко для вычитки: проблема → решение

Подробности — [product.md](product.md), [tech.md](tech.md), [plan.md](plan.md).

## Загрузка трека

1. **Видео в звуковом режиме скачивает весь MP4** (звука там 3–8%) →
   сервер отдаёт «виртуальный» M4A только со звуковой дорожкой из того же файла,
   побайтно, без копии на диске (T01).
2. **Целиком грузятся только файлы ≤ 32 МиБ** → лимит 128 МиБ. Видео в звуковом
   режиме идёт как виртуальный звук (T01, T02).
3. **Следующий трек грузится раньше, чем догрузился текущий** → подготовка
   следующего только после полной загрузки текущего (T04).
4. **«5 секунд» начала не учитывают обложку в MP3 и индекс в конце M4A**
   (старт 1,85 с) → сервер запоминает, где в файле начинается звук.
   Префикс = заголовок + 10 с, до 2 МиБ, хвост M4A — сразу (T03).
5. **Лишний HEAD-запрос перед следующим треком** (183 из 208 мс) →
   свой файл стартует сразу, право проверяет первый запрос догрузки (T05).
6. **Полоса не заполняется у загруженного трека** → шкала строится
   по загруженным байтам (T06).
7. **Догрузка блоками по 1 МиБ с паузами, зависание до 30 с** → один
   непрерывный поток до конца файла, таймаут 10 с и повтор (T02).
8. **Лишняя работа на клике** (перерисовка всей сетки, перемотка к 0) →
   перерисовываются только две карточки, `/library/ids` уходит после старта (T13).

## Фон и сайт

9. **Сводка 236 КБ каждые 3 с** (~280 МБ/ч) → запрос только изменений
   по ревизии, 10 с при открытой вкладке, задания отдельно (T07).
10. **Состояние плеера пишется 4 раза в секунду с очередью** → очередь пишется
    при изменении, позиция — раз в 5 с (T08).
11. **Нет сжатия JSON/JS/CSS, сборка перепроверяется** → `encode zstd gzip`
    в Caddy, кроме `/files` и обложек; долгий кеш `/assets` (T09).
12. **Запись активности Kaname на каждый запрос файла** → не чаще раза
    в минуту (T15).
13. **Белый экран при обрыве ответа** → `api()` выбрасывает ошибку,
    error boundary, плеер играет дальше (T11).

## Плейлисты, выдача, обложки

14. **Редактор, настройки и YouTube-подборки качают весь каталог 5,1 МБ**
    (до 5,6 с) → точечные запросы по страницам, теги из сводки (T10).
15. **Состав плейлиста после создания загружается дважды** → одна загрузка
    на ревизию (T10).
16. **Миниатюры заново создаются FFmpeg после каждого деплоя** → кеш
    на диске по hash файла, браузер не перезапрашивает (T12).
17. **Выдача повторяет счётчики тегов, очередь тормозит на длинном списке** →
    счётчики только при изменении, лёгкий DTO, виртуализация очереди (T14).

## Качество

18. **YouTube: выбирается AAC ~128 кбит/с и может перекодироваться,
    несовместимые файлы — в AAC с потерями** → для новых файлов лучший поток
    без перекодирования, несовместимый звук — во FLAC без потерь, HE-AAC
    играется как есть. Существующие треки не трогаем (T16).

Проверка всего — повторяемый замер на проде до и после каждого этапа (T17).
