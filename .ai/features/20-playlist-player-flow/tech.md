# Технические решения

Владелец согласовал продукт и поручил автономную реализацию. Технические решения ниже приняты в рамках этого поручения.

| Вопрос | Исходная система и выбранное решение |
|---|---|
| T01. Как показать плейлист в медиатеке | Карточка сейчас ведёт в редактор через страницу состава. Разделить элементы управления. В оболочке сайта хранить контекст плейлиста отдельно от обычных фильтров. Для своего плейлиста использовать существующие API состава с полным порядком ID и порционной загрузкой строк. Для сохранённого общего — действующий путь доступа и его порядок с закрытыми позициями. |
| T02. Кто определяет очередь | В приложении уже есть один PlayerProvider, очередь и каталог её записей. Каждый явный запуск плейлиста передаёт весь порядок и источник выбора, навигация лишь выбирает представление. Смена подборки на уже звучащем треке сохраняет его позицию. При конкурирующих действиях действует последнее намерение. |
| T03. Как сохранить звук при смене представления | Доступность фонового звука вычислять для источника записи. Отделить экран просмотра от выбора новой записи. Для записи с фоновым звуком сохранять ведущие часы и состояние воспроизведения при смене картинки, включая привязанный клип. У внешнего проигрывателя повторно проверять права и показывать причину ограничений. |
| T04. Как управлять сценой и громкостью | Использовать существующие разделение одиночного и двойного щелчков и разворачивание всей сцены. Применить их и к обложке. В мини-плеере вывести общие mute и range непосредственно в правой группе рядом с действием просмотра. |
| T05. Как доказать непрерывность | Проверить реальный локальный файл с движущимися часами, декодированием, паузой и очередью. Проверить обе точки открытия сцены и возврат через меню и историю браузера. |

Затронуты [сайт и плеер](../../map/web.md) и [плейлисты](../../map/playlists.md). Изменения относятся к браузерному клиенту. Модель владения, серверное вычисление порядка и качество источников используются в существующем виде.
