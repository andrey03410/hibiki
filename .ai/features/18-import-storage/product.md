## №19. Что занимает место

Импорт проходит в два шага. После загрузки Hibiki хранит ZIP для предпросмотра. По команде «Применить импорт» отдельное задание читает тот же ZIP. Успешное применение удаляет временную распаковку. Исходный файл остаётся в каталоге предпросмотра, а его размер продолжает входить в квоту Kaname без срока освобождения. Один предпросмотр сейчас можно применить несколько раз. **Контрольный перенос.** На пустом тестовом аккаунте использовано 0 байт. После импорта одного WAV задание завершилось успешно. Файл в медиатеке занимал 16 044 байта, входной ZIP — 16 834 байта, учёт показал **32 878 байт**. Временная распаковка исчезла. Проверены реальные файлы и SQLite, ответ службы прав Kaname задавался локально. Приведённые в issue 458 МБ — наблюдение автора обращения на его установке. ## №19. Согласованное поведение

Цель — после переноса пользователь может слушать записи, видеть результат задания и использовать освободившееся место для следующей загрузки. P01–P03 приняты к автономной реализации. Владелец уточнил, что квота ограничивает фактический объём пользовательских файлов, в том числе во время записи. Освобождение байтов следует за удалением файла. Агент по MCP получает оценку и может очистить архивы своего аккаунта.

### P01. Когда освобождать новый архив

**Решение.** После первого успешного применения освободить ZIP автоматически, как только завершатся все уже поставленные в очередь или выполняющиеся задания, которым он нужен. Пользователь видит результат импорта и состояние «Архив освобождён». Повторное нажатие «Применить» для успешно обработанного предпросмотра открывает результат. Двойное нажатие или повторный запрос MCP во время применения возвращает текущее задание. Для намеренного нового переноса после освобождения ZIP пользователь загружает архив заново.

Правило действует с момента первого успешного применения по новым правилам, в том числе для ZIP, загруженного до обновления. Для архивов, уже успешно применённых до обновления, действует P02.

Ограниченный срок хранения позволил бы повторить перенос без загрузки. При заполненной квоте пользователь ждал бы истечения срока или чистил хранилище вручную. Поэтому предлагается освобождать место сразу, когда это безопасно. Если применение завершилось ошибкой или отменено и доступен повтор, архив остаётся для повтора. То же правило действует, если из двух применений одного ZIP одно успешно, а второе ещё можно повторить.

### P02. Как вернуть место за прошлые импорты

**Решение.** В разделе «Настройки → Хранилище» показать действие «Освободить архивы завершённых импортов». До подтверждения пользователь видит количество подходящих ZIP, их суммарный размер и пояснение, что медиа, теги, плейлисты и история заданий сохранятся. После подтверждения — фактическое число удалённых архивов и освобождённый объём. При частичном сбое виден остаток, очистку можно повторить.

Очистка охватывает все старые успешно применённые архивы текущего аккаунта, включая задания за пределами последних 100 в списке. Каждый физический ZIP считается один раз. Неприменённые предпросмотры, ожидающие, выполняющиеся и доступные для повтора задания защищены. Если состав изменился между показом оценки и подтверждением, удаляются только всё ещё подходящие файлы. До добровольной очистки старый успешно применённый предпросмотр сохраняет прежнюю возможность повторного применения. После очистки доступен только сохранённый результат. Экспортные ZIP остаются доступны для скачивания. Альтернатива — разовая автоматическая уборка старых архивов при обновлении. Предлагается оставить выбор владельцу медиатеки: прежние предпросмотры допускали повторное применение.

### P03. Что показывает хранилище

**Решение.** В настройках хранилища показать лимит аккаунта и постоянный расход по категориям — медиа, архивы импортов, архивы экспортов и прочие учтённые файлы. Внутри архивов импортов выделить объём, который можно освободить сейчас. Отдельно показать место, временно зарезервированное текущими операциями. Свободное для следующей загрузки место учитывает эти резервы. Это позволит объяснить отказ в загрузке, даже когда постоянный расход ниже лимита. Для локального аккаунта без квоты показать занятое место и доступную очистку без числового лимита. Более узкий вариант — показывать только общий расход и размер доступной очистки. Он решает задачу удаления, но оставляет без ответа вопрос пользователя, чем занято остальное место. [Проверка доступного места](https://github.com/andrey03410/hibiki/blob/319f00fa0211388ee92ed30a372f29860c485609/apps/server/src/kaname.ts#L138-L153)

## №19. Критерии приёмки

| Сценарий | Наблюдаемый результат |
|---|---|
| Один успешный импорт в пустой аккаунт | После освобождения ZIP расход равен размеру импортированных медиа. Запись воспроизводится, теги и состав плейлиста сохранены. В истории виден успешный результат. |
| Предпросмотр готов, применение ещё не запускали | ZIP остаётся. Ручная очистка других импортов его пропускает. Позднее применение работает. |
| Ошибка, отмена или перезапуск во время применения | У доступного для повтора задания сохраняется ZIP. После успешного повтора место освобождается один раз. |
| Несколько заданий читают один ZIP | Один успех не прерывает соседнее задание. По завершении всех зависимых операций архив освобождается по P01. Повтор команды для очищенного предпросмотра возвращает результат. |
| В аккаунте накопились старые применённые ZIP | Оценка учитывает архивы любой давности. После подтверждения уменьшились и размер файлов на диске, и расход квоты. На освободившееся место можно загрузить файл. Повторная очистка уже удалённых ZIP показывает 0 байт. |
| Во время очистки файл удалить не удалось | Импорт остаётся успешным. Интерфейс показывает, сколько действительно освободилось. Повтор или восстановление после перезапуска приводит диск и квоту к одному результату. |
| Два аккаунта, рабочие импорты и готовые экспорты | Каждый видит и очищает только свои подходящие архивы. Чужие данные, активные импорты и доступные для скачивания экспорты сохраняются. Правила автоматического освобождения одинаковы для импорта с сайта и через MCP. |

В объём входят входные ZIP успешных импортов и объяснение расхода квоты. Удаление медиа, очистка экспортов и отдельное действие для отказа от неприменённого предпросмотра выходят за границы этой задачи.

## №20. Как поделиться смешанным плейлистом сегодня

1. Исходный автор открывает «Мои ссылки», выбирает ту ссылку, по которой составитель сохранил запись или плейлист, и включает «Разрешить слушать в плейлистах других пользователей». Разрешение по умолчанию выключено.
2. Составитель добавляет полученную запись в свой плейлист вместе с собственными и передаёт слушателю одну ссылку. Уже выданная ссылка тоже учитывает изменение прав. В окне «Поделиться» составитель видит число доступных позиций и причины пропусков. Разбивка появляется после создания ссылки, когда готов расчёт. Пожелание из issue о предпросмотре до создания ссылки остаётся отдельным улучшением. Для передачи плейлиста оно не требуется. [Окно выдачи ссылки](https://github.com/andrey03410/hibiki/blob/319f00fa0211388ee92ed30a372f29860c485609/apps/web/src/Sharing.tsx#L172-L217)
3. Вошедший слушатель видит треки в порядке составителя с указанием исходного автора. На закрытом месте отображается «Запись недоступна». Полученную запись можно слушать без копии и расхода квоты у слушателя. Разрешение на прослушивание само по себе не даёт слушателю права сохранить трек отдельно и передать его следующему человеку.
4. При отзыве или истечении последнего подходящего разрешения позиция снова закрывается для третьего слушателя. Исходный владелец по действующей ссылке на подборку может слушать собственную сохранившуюся запись и при выключенной дальнейшей передаче. Автор включает разрешение — доступны 3 из 3 в исходном порядке, число хранимых медиафайлов и записей учёта квоты сохраняется. После выключения разрешения новые запросы заимствованного файла отклоняются. Запрет отдельного сохранения делегированной записи ограничивает дальнейшую цепочку.
