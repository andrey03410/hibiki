# Проверка задачи 13

## Локальная приёмка

- Финальная тройка в порядке `npm test` → `npm run build` → `npx tsc --noEmit` прошла. Vitest завершил 385 тестов в 39 файлах. Интерфейс шеринга загружается отдельным модулем Vite.
- В Chrome с двумя разными аккаунтами проверены создание ссылки из попапа, число записей, смена срока на сутки у той же ссылки и возврат по исходному адресу после входа. Анонимный запрос получил 401.
- В Chrome воспроизвелись локальные WAV и MP4 по ссылке. Запрос Range вернул 206 и первые байты WAV, ответ не сохраняется в кэше. Прямой маршрут файла владельца у получателя вернул 404.
- Сохранение плейлиста оставило число записей и файлов получателя прежним. Уже открытая сохранённая подборка отразила изменение оригинала. Запрос удалённого из состава трека был закрыт, в открытой медиатеке у него появился статус недоступности. Копия другой записи, созданная из меню настоящим worker, продолжила воспроизводиться после отзыва в «Моих ссылках».
- Два настоящих клиента SDK MCP проверили выдачу и изменение срока, сохранение без файла, локальную копию и отзыв. Очередь копирования повторно проверяет доступ. Повторное копирование переиспользует файл с тем же хэшем.
- На локальном плейлисте из 2500 позиций выдача, чтение готового счётчика и изменение срока заняли соответственно 3,4, 1,7 и 2,9 мс без вызовов расчёта состава. Первое чтение готового состава заняло 30,4 мс. Замер выполнен на изолированной SQLite без сетевой задержки.
- Обе миграции применились к базе предыдущей версии. Существующая запись сохранилась, проверка внешних ключей прошла, маркер версии обновляется при правке.
- Независимое ревью нашло несогласованность фильтра доступности, ожидание Kaname внутри транзакции и устаревшие данные при смене источника плеером. После исправлений повторное ревью прошло, подтверждены все четыре точки повторной проверки и 45 профильных тестов.

Доказательства находятся в `storage/verification/13-media-sharing/` вне Git.

## Что посмотреть руками

1. Открыть нужную запись или плейлист и нажать «Поделиться». У плейлиста виден счётчик, готовую бессрочную ссылку можно скопировать или задать срок.
2. Открыть ссылку во втором аккаунте, воспроизвести и сохранить плейлист. Изменить состав в первом аккаунте и дождаться обновления во втором.
3. Добавить одну запись и запустить «Создать локальную копию», затем открыть «Мои ссылки» под «Заданиями» и отозвать ссылку. У созданной копии остаётся собственный источник.
