# Технические решения

## Исходная система

- [Плеер](../../map/web.md) хранит очередь, исходный порядок, позицию и режимы через
  настройки. React API работает с локальным media element и YouTube IFrame.
- [Медиатека](../../map/media.md) хранит независимые Item, Source, MediaFile.
  Загрузка локального файла уже умеет прикреплять его к существующему item.
- [Правила](../../map/playlists.md) разбираются схемой Zod и вычисляются общим ядром
  для HTTP и MCP. Ручной порядок и ссылки на плейлисты уже поддерживаются.
- [Jobs](../../map/jobs.md) и [YouTube](../../map/youtube.md) используют worker, SQLite,
  ограниченные внешние процессы и запросы только к каноническим YouTube URL.
  Текущий импорт допускает частичные успехи: для обновления состава это опасно.
- [Архив](../../map/portability.md) переносит библиотеку через preview/apply.
  HTTP принимает cookie и MCP-токены. Приватным дополнениям нужен явный браузерный гейт.

## Решения

### T01. Очередь
- **Варианты:** вести два переписываемых порядка; хранить только фактический порядок.
- **Решение:** React и чистые операции по ID, один фактический порядок. Перестановка
  меняет индекс, не активный media key; сохранение использует существующий POST ручного
  плейлиста. Опциональный контекст исходного плейлиста передаётся из точек запуска.
  При восстановлении старых настроек сохранять читаемость прежних полей.

### T02. История, правила и выгрузка
- **Варианты:** писать поток событий, выполнять всё на клиенте или фиксировать попытку.
- **Решение:** плеер измеряет проигранные интервалы и сохраняет идемпотентный итог
  попытки; сервер проверяет владение, приватный доступ, границы полей и сбор настройкой.
  SQLite хранит попытки бессрочно и сводку отдельно. CSV читается батчами, интерфейс —
  страницами; порог 1 ГБ только информирует. Очистка после превью, выборочная сохраняет
  сводку; полный сброс сознательно меняет условия. Агент получает только явно
  предоставленные агрегаты для предложения, не разрешение удалить данные.
  Расширить AST правилами истории и избранного, сохранив старые определения и проверки
  графа. Состав вычисляется по журналу/сводке владельца, не возвращая их в MCP DTO.

### T03. Источники
- **Варианты:** заменить внешний ключ; создать дубликат; добавить новый Source.
- **Решение:** хранить предпочтение на Item. Сервер выдаёт превью кандидата и проверяет
  его владение при подтверждении; файл проходит существующий pipeline media.
  Не забирать YouTube key у другого item. MCP только создаёт предложение
  из ссылки и объяснения; применение требует UI-сессии владельца.

### T04. Синхронизация
- **Варианты:** периодически переимпортировать весь плейлист; обновлять по полному снимку.
- **Решение:** отдельная связь с URL, последним снимком external ID → item ID,
  локальными исключениями и дополнениями, превью и отчётом. Порядок материализуется как
  обычный состав плейлиста для существующих зависимостей; сравнение по external ID,
  а не по выбранному источнику. Новые записи переиспользуются, изменения атомарно
  публикуются после проверки актуальности; неполный ответ не считается удалением.
  Worker проверяет по сроку и режиму, с сигналом остановки; отчёт и уведомления
  хранятся в базе, повтор результата не создаёт новое уведомление.

### T05. Медиатека и приватные данные
- **Варианты:** индекс внешнего поиска; общие чистые фильтры над личной медиатекой.
- **Решение:** использовать существующий snapshot для небольшого локального каталога
  и новые комбинируемые фильтры; листинг не загружает подробную историю.
  Избранное — свойство Item. Приватные заметки четырёх типов выдаются только
  браузерным маршрутом, не через обычные DTO. Архив из браузера включает заметки
  и сводку только по явной опции. При переносе используем переназначение IDs и
  сохраняем уже заполненные целевые данные. MCP не читает приватный архив.

## Карточки и проверки

Обновить web, media, playlists, youtube, jobs, mcp и portability по факту реализации.
Использовать изолированное тестовое storage, не рабочий аккаунт. Пройти тройку,
затем браузер с реальными файлами, встроенный плеер, настоящий MCP, реальную сверку
YouTube и перенос с изоляцией аккаунтов. Записать evidence и пройти свежее ревью.
