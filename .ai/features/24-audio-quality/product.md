# Продуктовые решения

Решения приняты агентом в автономном режиме, разрешённом владельцем.

## Цель

Слушатель видит, в каком качестве хранится каждый трек, и может быстро найти треки,
которые стоит заменить: звук с потерями и низким битрейтом, а также Hi-Res. Внешний агент
через MCP получает те же данные и может выбирать треки для замены без открытия сайта.

## Сценарии

1. В выдаче медиатеки рядом с длительностью каждой записи виден небольшой значок:
   `FLAC 24/96`, `FLAC 16/44.1`, `AAC 128`, `MP3 320`, `Opus 160`. Цвет значка показывает класс.
2. В карточке записи на вкладке «Источники» у каждого локального файла указаны
   контейнер, кодек и профиль, битрейт, частота, разрядность (только для без потерь), каналы,
   размер. Для видео — кодек, профиль, разрешение, fps и битрейт.
   Подготовленная копия помечена, рядом указано качество оригинала.
3. Фасет «Качество» в панели медиатеки: классы «Hi-Res», «Без потерь», «С потерями»,
   под каждым кодеки с числом записей в текущей выдаче. Выбор класса берёт все его кодеки.
4. Сортировка «Лучшее качество» и «Худшее качество».
5. Агент вызывает `media_list` с `audioQuality: ["lossy"]` и `sort: "quality-asc"`
   и получает худшие треки первыми, с подробными метаданными источников.

## Решения

### P01. Классы качества

- Варианты: показывать только имя кодека; классы без потерь/с потерями; три класса с Hi-Res.
- Рекомендация: три класса.
- **Решение:** `hires` — без потерь и (разрядность > 16 или частота > 48 кГц);
  `lossless` — FLAC, ALAC, PCM (WAV/AIFF), WavPack, APE, TTA и т. п.; `lossy` — всё
  остальное, включая ADPCM, AAC, MP3, Opus, Vorbis, WMA. Несжатый PCM относится к «без потерь»:
  по качеству он равен FLAC.

### P02. Подпись значка

- Варианты: имя кодека; имя и одна главная цифра; полный набор параметров.
- Рекомендация: имя и одна главная цифра.
- **Решение:** без потерь — `FLAC 24/96` (разрядность/частота в кГц); с потерями —
  `AAC 128` (битрейт в kb/s), без известного битрейта — только имя. Имя кодека учитывает
  профиль и контейнер: `HE-AAC`, `WAV`, `AIFF`, `ADPCM`. Полные данные — во всплывающей
  подсказке и в карточке.

### P03. Чьё качество показывает запись

- Варианты: лучший из источников; источник, который играет; оригинал.
- Рекомендация: источник, который играет по умолчанию, но для подготовленной копии — качество
  её оригинала. Копия из ADPCM, записанная во FLAC, не становится звуком без потерь.
- **Решение:** порядок выбора — звук назначенного видеоряда, предпочтительный источник,
  первый доступный локальный источник. Для подготовленной копии берётся качество оригинала.
  Записи только с YouTube значка не получают.

### P04. Фильтр

- **Решение:** одно поле `audioQuality` — список значений `hires`, `lossless`, `lossy`,
  имя формата (`flac`, `aac`, …) или пара `класс.формат` (`hires.flac`). Значения
  объединяются через «или». Фасет на сайте показывает классы и форматы с числами записей.
  Остальные фильтры и теги действуют вместе с ним через «и».

### P05. Сортировка

- **Решение:** `quality-desc` («Лучшее качество») и `quality-asc` («Худшее качество»).
  Порядок: Hi-Res, без потерь, с потерями. Внутри без потерь — по разрядности и частоте,
  внутри с потерями — по битрейту. Записи без проанализированного локального файла идут
  в конце при любом направлении.
  Кодеки с потерями не взвешиваются по эффективности: так порядок проще объяснить.

### P06. Существующие файлы

- **Решение:** worker после выкладки сам анализирует все файлы всех аккаунтов (FFmpeg читает
  только заголовки) и повторяет проверку каждые 10 минут для файлов без данных. Файлы и треки
  не меняются. Пока анализ не завершён, у записи нет значка.

## Не входит

- Новые форматы файлов, перекодирование и замена треков.
- Правила плейлистов по качеству.
- Фильтр по качеству для записей, доступных только по чужой ссылке: значок у них есть,
  но фильтр учитывает только свои файлы.
