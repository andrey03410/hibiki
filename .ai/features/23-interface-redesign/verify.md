## Живая проверка плавности

Продакшен-сборка на `127.0.0.1:8790`, Chromium headless 1440×900, аккаунт
design_demo. Скрипт — `perf.mjs`. PerformanceObserver собирает `longtask` и
`layout-shift` по сценариям: загрузка, прокрутка, фасет, выбор двух жанров, вкладка
и крошка, «Обзор», сброс, подсказки поиска, открытие панели, вкладки и «След.»,
закрытие, «Карточки», переходы по меню.

- **Итоговый прогон после ревью:** 233 мс long tasks на 13 сценариев (сброс 71, поиск 72,
  первый переход по меню 90), CLS 0,0016.
- **Сдвиги макета:** CLS при загрузке 0,0016 (норма < 0,1). В остальных сценариях — 0.
- **Long tasks:** прокрутка, фасет, крошки, «Обзор», панель и её вкладки — без long tasks
  в большинстве прогонов. Задачи 70–110 мс остались при полной замене 100 строк
  (сброс фильтров, ввод поиска) и при первом переходе на ленивый экран.
- **`content-visibility` для строк** (`ab.sh`, по 3 прогона): суммарное время long tasks
  897 → 290 мс. Сброс фильтров 162–305 → 73–91 мс, поиск ~185 → ~75 мс, «Карточки»
  ~130 → 0 мс, открытие и закрытие панели 55–149 → 0 мс.
- Профиль JS (`prof.mjs`) не показал горячих функций приложения. Основное время
  уходит на раскладку и отрисовку строк, поэтому и помогло `content-visibility`.

Трассировка Chrome (`trace.mjs`) с подробными категориями сама искажает время
задач, поэтому выводы сделаны по PerformanceObserver.

## Ревью

Свежий ревьюер (отдельный агент) прочитал весь дифф. Права и параметризация SQL
в `section-covers` и `tagSets` в порядке. Очередь автосохранения, отмена, порядок
хуков, поповеры и ключи кешей тоже без замечаний.

Исправлено (коммит `ef31299`, тесты добавлены там, где логика чистая):

1. Массовое «С вокалом» стирало уже указанные голоса. Теперь вокальные записи
   не меняются, остальные получают вокал без замены голосов.
2. Повторное открытие записи до обновления списка показывало старые теги, и
   следующее изменение могло их перезаписать. Панель начинает с последнего
   сохранения (`startDraft`), пока список не догонит.
3. В выдаче «Требуют разметки» «Пред./След.» выключались, когда запись уходила из
   списка. Теперь переход идёт от её последней позиции.
4. После закрытия панели фокус терялся: диалог удалялся без `close()`. Панель
   остаётся смонтированной на время закрытия, фокус возвращается в строку.
5. Набор архивных или удалённых тегов делил группу «Метки» с настоящим выбором и
   портил счётчики «Меток». Сервер теперь пропускает для счётчиков группы только
   её первый набор (тест в `library-pages.test.ts`).

Повторная проверка ревьюером подтвердила исправления. По её итогам черновик
запоминается уже при начале сохранения, «Играть» в панели запускает запись и
после её выхода из выдачи, а вкладки сохраняют прежние счётчики до прихода новых.
Не исправлено: повторное открытие той же записи в первые 320 мс после закрытия
сохраняет прежнюю вкладку панели.

Мелочи: защита кеша совпадений при `tagSets` на сервере, счётчики без мигания
общих чисел при выбранных тегах, массовая разметка перечитывает записи после
конфликта ревизии.

Оставлено: смена тега запускает пересчёт счётчиков по группам (до 6 запросов,
19 мс на 3000 записях, кеш на 8 ключей). Для личной медиатеки этого достаточно.
Кеш по отдельным группам — в «Хвостах», если медиатека вырастет.

## Отступления от плана

- Каталог тегов `/tags` сохранил дерево и получил новый стиль. Колонки источника
  есть в панели разметки, перенос их в каталог — в «Хвостах».
- Строки плейлиста внутри медиатеки (`PlaylistLibrary.tsx`) пока в прежнем виде.
- Массовое «С вокалом» не выбирает голоса: записи, которым он ставится, получают вокал без голоса. Голос уточняется в панели записи.
- Прежний `tagMode` из sessionStorage не переносится. После обновления выбранные
  теги восстанавливаются с логикой по группам.
