# Технические решения

## Исходная система

- Сайт — `apps/web/src/main.tsx` (оболочка, медиатека, строки, детали записи,
  массовая разметка, плейлисты), `TagNavigation.tsx` (правая панель),
  `LibrarySearchControls.tsx` (строка поиска и фильтров), `player.tsx`
  (сцена `/player` и мини-плеер), `TagsPage.tsx`, `JobsPage.tsx`, `SettingsPage.tsx`.
- Стили: `styles.css` (3,7 тыс. строк, ~440 жёстко заданных цветов), отдельные
  `library-view.css`, `taxonomy.css`, `queue.css`, `library-search.css` и др.
  Токены — пять переменных в `:root`. Шрифты DM Sans и Manrope лежат в `public/fonts`.
- Сервер: `apps/server/src/library-pages.ts`. `tagFilter` поддерживает один
  тег, «И» (`HAVING count(DISTINCT ancestor)`) и «ИЛИ». `facetCounts` считает
  счётчики всех тегов одним `GROUP BY` по `ancestry`; ключ `facetToken` не
  включает теги, поэтому счётчики не зависят от выбранных тегов и кешируются
  (8 ключей) и пропускаются клиентом по `countsKey`.
- Запись: `PATCH /items/:id` принимает `tagIds`, `performance`, `voices`,
  `completeClassification` — последний флаг лишь проверяет полноту.
  Массовая правка — `POST /items/batch` с `expectedRevision`.

## Решения

### T01. Логика «И между группами, ИЛИ внутри»

- Варианты: новый `tagMode: "groups"` с поиском групп на сервере; явные наборы.
- Рекомендация: необязательное поле `tagSets: {group, ids, all?}[]` в
  `librarySearchSchema`. Наборы объединяются «И»; внутри набора «ИЛИ» или «И»
  (`all`). Каждый набор — тот же подзапрос, что сейчас у одного режима.
  Клиент строит наборы по группам выбранных тегов. `tagIds`/`tagMode`
  остаются для MCP и старых клиентов; при наличии `tagSets` они не используются.
- **Решение:** принято. Схема правил плейлистов не меняется.

### T02. Счётчики фасетов с учётом наборов

- Рекомендация: без наборов — ровно прежний один запрос. С наборами —
  `1 + число наборов` запросов `facetCounts`: общий (все наборы) для тегов
  невыбранных групп и «без своего набора» для тегов каждой выбранной группы.
  `facetToken` включает наборы; кеш на 8 ключей сохраняется.
- **Решение:** принято. Замер на синтетической медиатеке 3 000 записей до и после
  записывается в verify.md; запрос без тегов не меняется.

### T03. Стили

- Варианты: переписать всё; новый слой поверх.
- Рекомендация: `design.css` — токены, примитивы (Chip, Facet, Popover, Drawer,
  Segmented, Toast, Dock) и анимации, подключается последним. Старые переменные
  `--muted/--purple/--panel/--border/--text` переопределяются новыми значениями,
  чтобы второстепенные экраны сразу перешли в новую палитру. Экраны, которые
  меняются по разметке (медиатека, строка, разметка, док, плеер, теги,
  плейлисты, задания, настройки), получают собственные стили в `design-*.css`,
  а мёртвые правила старых файлов удаляются (`taxonomy.css` для панели и т. п.).
- **Решение:** принято.

### T04. Шрифты

- **Решение:** Onest (OFL) для интерфейса, Manrope для заголовков, оба
  локально в `public/fonts` (woff2, latin + cyrillic), без внешних CDN.
  DM Sans удаляется.

### T05. Цвет обложки

- **Решение:** клиентская функция усредняет цвет уменьшенной обложки (canvas
  16×16, same-origin `/api/items/:id/artwork?size=thumb`), результат кешируется
  в памяти по URL; переменная `--amb` на оболочке плавно меняется (600 мс).
  Ошибка чтения — нейтральный акцент. Сервер не затрагивается.

### T06. Автосохранение разметки

- **Решение:** панель хранит черновик; через 450 мс после последнего изменения
  отправляет `PATCH /items/:id` с полными `tagIds/performance/voices`.
  Последовательные сохранения идут по одному, следующий черновик ждёт
  предыдущий ответ. Тост «Отменить» отправляет предыдущее состояние. Название
  сохраняется по blur/Enter. Обновление обзора — после успешного сохранения
  (как раньше после «Сохранить»).

### T07. Анимации

- **Решение:** CSS-переходы и `@starting-style` для появления поповеров, панели,
  чипов и тостов; длительности 120–320 мс; `prefers-reduced-motion` отключает
  движение. Строка трека фиксированной высоты, скелетоны при загрузке, обложки
  проявляются по `load`. Никаких JS-библиотек анимации.

### T08. Структура кода

- `LibraryFilters.tsx` — вкладки источника, крошки, фасеты, строка активных
  фильтров, подсказки поиска, вид «Обзор». Заменяет `TagNavigation.tsx`.
- `ItemDrawer.tsx` — панель записи (разметка с колонками, вкладки) вместо `EditItem`.
- `BulkTagger.tsx` — поповер массовой разметки вместо `BatchTags`.
- `design/` — общие примитивы (`Chip`, `Popover`, `Drawer`), `tag-colors.ts`,
  `ambient.ts`. Логика без DOM — с юнит-тестами (наборы тегов, частичные
  состояния, цвета).

## Живые проверки

- Браузер: медиатека, фасеты, крошки, подсказки, «Обзор», панель разметки с
  автосохранением и отменой, массовая разметка, плеер, плейлисты, теги, задания,
  настройки; запись производительности (Performance) на прокрутке и открытии
  поповеров/панели — без long tasks > 50 мс и без layout shift.
- Сервер: замер `/library/page` с тегами и без на 3 000 записях.
- Прод после деплоя: аккаунт andrey, только чтение.
