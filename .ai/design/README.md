# Дизайн-система «Тихий звук»

Единый визуальный язык сайта Hibiki. Введена задачей
[23. Редизайн интерфейса](../features/23-interface-redesign/README.md).
**Новые экраны и правки расширяют эту систему, а не заводят свою.** Нужен
новый цвет, радиус, тень, длительность или примитив — добавь токен/класс в
`apps/web/src/design.css` и строку в этот документ, затем используй его.

## Принципы

1. **Тихо по умолчанию.** Тёмный фон, мягкие поверхности без рамок, один
   акцент. Управление проявляется по наведению и выбору, а не висит всегда.
2. **Теги — навигация.** Тег всегда выглядит как чип цвета своей группы;
   выбор тега — это фильтр, а не форма.
3. **Мало одновременно.** Фасет открывается поповером, детали записи —
   боковой панелью. На экране один главный вопрос.
4. **Никаких скачков.** Фиксированные высоты строк, скелетоны вместо пустоты,
   плавное появление; макет не прыгает при загрузке данных и обложек.
5. **Цвет музыки.** Фон оболочки слегка окрашен цветом обложки текущего трека
   (`--amb`), цвет меняется за 700 мс.

`design-*.css` и удаляй мёртвые правила старого файла.

| Форма | радиусы `--r-xs 6`, `--r-sm 9`, `--r 12`, `--r-lg 18`, `--r-xl 24`; тени `--shadow-pop`, `--shadow-float` |

Полупрозрачные смеси строятся `color-mix(in oklab, <цвет> N%, transparent)`.
Цвета групп продублированы в `tag-colors.ts` (`groupColors`) — меняй оба места.

## Цвет тега

`tagColor(tag)`: собственный цвет пользователя важнее всего (кроме цвета по
умолчанию `#b8a5ff`); у настроений свой оттенок по названию (Спокойная —
голубой, Эпичная — оранжевый, Мрачная — серо-лиловый и т. д., неизвестные —
из запасной палитры по хешу); остальные теги — цвет группы.

## Движение

- Только CSS: `transition`, `@starting-style` для появления, `allow-discrete`
  для `display/overlay`. Библиотеки анимации не подключаются.
- Длительности 120–320 мс; цвет оболочки — 700 мс. Анимируются `opacity`,
  `transform`, цвета; ширина/высота/top — нет (кроме заранее зарезервированного места).
- `prefers-reduced-motion: reduce` гасит движение глобально (конец `design.css`).
- Списки не анимируют каждую строку при прокрутке; новые чипы — `.enter`.

## Раскладка оболочки

- Сайдбар слева 232 px: бренд, «Медиатека / Плейлисты / Теги / Задания»,
  плейлисты с мини-обложками, «Настройки» и пользователь внизу.
- Док мини-плеера плавает снизу по центру области контента (стекло, радиус 18,
  шкала прогресса по верхнему краю). Контент резервирует место под док.
- Заголовок страницы: Manrope 34/800, подпись `--text-3`.

## Медиатека (эталон экранов)

- Вкладки корней источника → хлебные крошки текущего узла («внутри» / «рядом»).
- Фасеты-поповеры: Исполнитель, Жанр, Настроение, Метки, Исполнение, Ещё.
  Логика: И между группами, внутри группы «Любой из» или «Все»
  (`tagSets` в `/library/page`). Счётчики фасета считаются без выбора своей группы.
- Строка активных фильтров: чипы с крестиком, «И» между группами, «Сбросить».
- Виды: «Список», «Карточки», «Обзор» (плитки дочерних разделов источника).
- Строка трека 60 px: выбор · обложка 44 px · название и исполнители · последние
  два уровня источника · до двух тегов и «+N» · длительность · действия по наведению.
  Сетка задаётся через `.item-collection .collection-results > .collection-entry`,
  ширина колонок — `@container` (980 и 640 px).
- Строки и карточки — `content-visibility: auto` с `contain-intrinsic-size`.
  Всё, что выпадает за пределы строки, делай поповером (top layer): обычный
  абсолютный блок внутри строки обрежется. Исключение — старое меню `.row-menu`,
  для строки с ним `content-visibility` выключается через `:has(.dropdown)`.

## Как расширять

1. Ищи готовый примитив здесь. Не нашёл — добавь в `design.css` с префиксом
   `ds-` и опиши в таблице выше.
2. Цвета — только токены; новый смысловой цвет — новый токен.
3. Экранные стили — в `design-<экран>.css`, импорт в `main.tsx` после `design.css`.
   CSS, импортированный внутри компонента, попадает в сборку раньше `styles.css`
   и проигрывает старым правилам. Для лениво загружаемых экранов (теги, ссылки)
   повышай специфичность (`.directory-page …`, `:root .directory-menu`).
4. Проверка: живой браузер на продакшен-сборке (8790). Сдвигов макета (CLS) при
   поповерах, панели и прокрутке быть не должно; long tasks > 50 мс допустимы только
   при полной замене выдачи (около 80 мс на 100 строк в headless Chromium).
   Скрипты замеров задачи 23 — `storage/verification/23-interface-redesign/perf.mjs`
   и `ab.sh` (вне git, локально).
