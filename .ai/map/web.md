# Сайт и плеер

## Код и экраны

`apps/web/src/main.tsx` — React/React Router-приложение: вход/регистрация,
медиатека `/`, плейлисты `/playlists` и `/playlists/:id`, теги `/tags`,
задания `/jobs`, настройки `/settings`. `styles.css` задаёт интерфейс ПК,
`api.ts` — API-клиент и форматирование. Vite-конфиг — `apps/web/vite.config.ts`.
В разработке сайт на 5174, после build его отдаёт сервер 8790.

В медиатеке: поиск, kind/local/tag-фильтры, сортировка, загрузка файлов,
YouTube single/playlist, редактирование названия/тегов и пакетная разметка.
Плейлисты поддерживают ручные items и редактор составных правил с preview,
объяснениями/исключениями и стабильным порядком; audio/video допустимы вместе.
Задания показывают progress и отчёт, отмену/повтор, скачивание export
и применение завершённого import preview. Настройки создают/отзывают MCP-токены,
дают адрес подключения и экспорт/импорт. Библиотека/задания обновляются опросом.

## Постоянный плеер

`player.tsx` содержит `PlayerProvider` над маршрутами; `player-model.ts` —
выбор source, восстановление и поиск следующего доступного item. Часть логики
shuffle/queue — в `packages/core/src/queue.ts`. Переходы по сайту не монтируют
плеер заново. Native audio/video и видимый YouTube IFrame работают в одной очереди.

Локальные источники с streamUrl приоритетны; явно unavailable пропускаются.
Несовместимый оригинал недоступен для плеера, доступная копия того же item
подготовлена сервером — [media](media.md). При ошибке source плеер пробует следующий,
затем пропускает item с сообщением; сама запись остаётся в библиотеке.

Очередь — снимок ID при старте, а не живая подписка на правила плейлиста.
Shuffle один раз переставляет очередь с сохранением текущего item; originalQueue
позволяет вернуться к исходному порядку. Есть next/previous, seek, громкость,
повтор off/all/one, список очереди и fullscreen видео. Previous после нескольких
секунд сначала возвращает текущий item в начало. Локальный seek использует HTTP Range.

Queue/index/position/volume/repeat/shuffle сохраняются в localStorage на аккаунт
и через `/api/settings` раз в 5 с/при уходе со страницы. Удалённые IDs фильтруются
при восстановлении; после reload плеер остаётся на паузе до пользовательского
действия. После применения архива состояние плеера загружается заново, чтобы старый
клиентский snapshot не затёр перенесённые настройки. Ошибка сохранения показывается.
Media Session API связывает основные действия с системными медиакнопками.

## Ограничения и проверка

Цель — ПК/браузер. Обычное локальное воспроизведение может продолжаться в свёрнутом
окне; фактическое поведение проверяется на целевой машине. Сон, выгрузка вкладки
и гарантированный YouTube-background не обещаются. YouTube iframe остаётся видимым;
autoplay/встраивание/сеть контролируются браузером и провайдером, скрытого обхода нет.

`player-model.test.ts` проверяет local/YouTube fallback, недоступные items,
перемещение по смешанной очереди и восстановление. `packages/core/src/queue.test.ts`
проверяет shuffle/repeat и индексы. В живом браузере пройти upload audio/video,
правила/preview/explain, audio → video → YouTube, seek/volume/shuffle/repeat,
маршруты, reload, import settings и сворачивание. Проверять decoded frames/time
и реальный звук; состояние кнопки play само по себе не доказывает воспроизведение.

При смене источника того же item (например, закончилась загрузка YouTube) плеер
передаёт новому media текущую позицию. Переключение на другой item начинает его
с нуля; восстановленный сеанс использует сохранённую позицию.
