# Фоновые задания

## Код и жизненный цикл

`apps/server/src/jobs.ts` содержит `JobsService`; `apps/worker/src/main.ts`
запускает цикл `runOnce`. Job в SQLite сохраняет input/result JSON, состояние,
progress `0..1`, completed/total, attempt, leaseUntil и cancelRequested.
Состояния: `queued`, `running`, `done`, `failed`, `cancelled`.
HTTP и MCP возвращают jobId; закрытие клиента не останавливает работу.

Worker выбирает старейшее queued/просроченное running задание и захватывает его
условным update по состоянию/attempt. Lease — 30 с, heartbeat — раз в секунду.
Публикация прогресса и done проверяет lease, attempt и отсутствие отмены;
устаревший worker не должен перезаписывать результат другого.
Пустая очередь опрашивается через 750 мс. Предельное число попыток — три.

Просроченная работа подхватывается после рестарта. Ручной retry доступен только
failed/cancelled, пока лимит не исчерпан. Ошибка не вызывает бесконечных повторов.
`stop()` отменяет активные процессы; при штатном останове незавершённое задание
возвращается в queued с возвратом попытки. Даже остановка на третьей попытке
не оставляет вечное queued; старые queued с исчерпанным бюджетом получают failed. Отмена через UI/MCP пишет флаг в БД, поэтому её видит
отдельный процесс worker; queued отменяется сразу, running — через heartbeat/AbortSignal.

## Виды работы

| Kind | Поведение |
|---|---|
| `youtube-import` | Состав single/playlist, item на позицию, исходное title и отчёт added/existing/unavailable/errors |
| `youtube-refresh` | Проверка внешних источников одного item или всей библиотеки |
| `youtube-download` | Audio/video в локальные sources существующего item |
| `shared-copy` | Явная собственная локальная копия записи, сохранённой по ссылке |
| `export` | Потоковый ZIP с manifest и опциональными файлами |
| `import` | Сначала безопасный preview; применение — отдельное задание |

Импорт YouTube сохраняет entries и позиции после шагов: завершённые позиции
пропускаются при повторе, ошибочные можно обработать снова. Один сбой не отменяет
успешные добавления. Позиция flat playlist без названия и известной недоступности
дополнительно проверяется по video ID (до 30 с, только metadata). Подтверждённое
удаление/закрытие сохраняет item как unavailable; сетевая ошибка оставляет unknown
и предупреждение, а не объявляет удаление. Уточнённые entries сохраняются вместе
с прогрессом, поэтому рестарт не требует повторять завершённую работу.
Скачивание пишет временные файлы в `storage/jobs/:id/`,
затем использует `LibraryService.importLocal` с signal и очищает download-каталог.

`shared-copy` выбирает доступный через ссылку локальный файл или YouTube. Для
YouTube действуют обычные права на скачивание. Локальный импорт проверяет квоты,
а перед публикацией проверяет актуальность ссылки и lease задания в той же
транзакции. Повторная копия переиспользует файл получателя с тем же хэшем.

Архив копируется в каталог задания до ответа на upload, чтобы удаление временной
загрузки не уничтожило будущую работу. `applyImport(owner, previewJobId)` требует
успешный завершённый preview с `canApply` и hash. Перед применением заново проверяются
хэш всего архива, содержимое и владелец preview. В отчёте есть количества,
совпадения, отсутствующие файлы и замечания о сохранении существующих названий.
Прямой `create(import, {apply:true})` запрещён. Подробности — [portability](portability.md).

Отдельный цикл worker сверяет связанный YouTube-плейлист раз в шесть часов,
проверяя наличие просроченной работы раз в минуту. Он работает параллельно
обычным заданиям, передаёт AbortSignal и не проверяет ручной режим.

При старте worker заполняет метаданные воспроизведения существующих файлов по 64 строки.
Он открывает файлы только на чтение, сверяет размер и проверяет доступ владельца.
Версии и значения публикуются одним условным обновлением. Прерывание допускает
повторный запуск. Команда `npx tsx --env-file-if-exists=.env apps/worker/src/main.ts --backfill-playback`
выполняет только этот проход и выводит число обновлённых и пропущенных файлов.
Отсутствующий файл остаётся кандидатом для следующего запуска. Ежедневная
очистка удаляет осиротевшие производные обложки из кеша.

## Как проверить

`jobs.test.ts` проверяет владение, claim, lease, восстановление,
частичный import, отмену/повтор и preview → apply. Вручную запустить реальное
скачивание/импорт, закрыть клиент и перезапустить worker между шагами;
проверить сохранённые позиции, отсутствие дублей и доступность готового файла.
Отдельно отменить работу из другого процесса и проверить прерывание FFmpeg/yt-dlp.
Чужой jobId не должен возвращать статус, архив или изменять состояние.

В режиме Kaname worker повторно проверяет назначение перед началом каждого задания и во время heartbeat долгой операции. Учитываются роль и локальная приостановка. Проверки прав также выполняются при фоновой синхронизации плейлистов и при обратном заполнении метаданных. Администратор может отменить задание обычного участника в /admin.

Worker один раз заполняет версионированные подсказки начала звука, положения концевого индекса и размера виртуальной дорожки. Он читает заголовки исходников ограниченными порциями. Ежедневная очистка удаляет невостребованные производные обложек из каталога кеша.
