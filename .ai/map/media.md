# Медиатека и локальные файлы

## Код и данные

`apps/server/src/library.ts` содержит `LibraryService`: owner-scoped snapshot,
импорт локального файла/YouTube, названия, теги, правила плейлистов и настройки.
`itemDto` формирует источники со `streamUrl=/files/:fileId`; размер `BigInt`
из Prisma переводится в JSON-число. Схема БД — `apps/server/prisma/schema.prisma`.
Runtime-контракты — `packages/contracts/src/index.ts`.

## Обложки аудио

`artwork.ts`: авторизованный `/api/items/:id/artwork` извлекает embedded cover
из локального audio source, в том числе аудиокопии YouTube/video item. DTO вычисляет
source.thumbnail для такого источника; URL не записывается в БД/manifest. Если
дериватив потерял cover, endpoint сначала проверяет сохранённый оригинал.
Полный перенос оригиналов сохраняет обложки без новых моделей/миграций.

JPEG/PNG/WebP распознаются по сигнатуре, результат до 5 МиБ. Общий бюджет чтения
метаданных — 8 МиБ и 4096 операций tokenizer, отдельная allocation ограничена;
большие audio/free boxes пропускаются через seek, не расходуя read budget.
Это ограничивает также множество FLAC PICTURE blocks, не только одну обложку.
Много метаданных, отсутствие/ошибка cover дают 404 и fallback в плеере.
LRU до восьми результатов, проверка owner/item/file и наличия/mtime оригинала
на каждом запросе. Ответ private,no-cache, Vary Cookie/Authorization, nosniff.
`strtok3` — прямой dependency для ограниченного file tokenizer.

Item сохраняет собственное `title`, `originalTitle`, kind audio/video и связи.
Недоступность относится к source и не удаляет item. Обновление YouTube сохраняет
переименованное пользователем название и теги. Начальные теги аккаунта —
«Любимое», «Аниме», «OST»; свои теги создаются и редактируются отдельно.

YouTube узнаётся по owner/provider/videoId, файл — по owner/SHA-256.
`importLocal(..., {itemId})` добавляет источники к существующему item без замены
его названия и ID. Одинаковый файл допускается у разных items как отдельная связь;
физическая копия внутри owner переиспользуется. Два одновременных обычных импорта
одного файла повторно проверяют источник внутри транзакции и не создают лишний item.
YouTube upsert также повторно проверяет идентичность внутри транзакции.
Удаление item/тега/плейлиста с явными зависимостями в правилах запрещено.
При удалении item его ordering-ссылки manualOrder и обе очереди очищаются
транзакционно; позиция текущего оставшегося item сохраняется. setSettings
нормализует queue/originalQueue и текущий индекс по исходному ID.

## Замена источника

`replacement.ts` проверяет новый источник в карточке записи. Превью показывает его
название и длительность при наличии. Для YouTube сервер проверяет метаданные
конкретного ролика, а доступность во встроенном плеере выясняется при запуске.
Ссылка, уже привязанная к другой записи владельца, вызывает конфликт.

Подтверждение добавляет источник к тому же Item и записывает
`preferredSourceId`, сохраняя поля записи, включая её длительность, и прежние
связи. Для несовместимого локального файла предпочтительной становится
подготовленная копия. Новое предпочтение действует со следующего запуска.
Предложение агента содержит ссылку и объяснение. Для его проверки, применения
и отклонения требуется вход в Hibiki через браузер.

Файл превью находится в `storage/uploads/replacements/` до подтверждения или
отклонения. Сервер удаляет временный файл после обработки и периодически
очищает оставленные загрузки старше суток.

## Импорт и совместимость

`media.ts` анализирует файл через music-metadata и FFmpeg, считает SHA-256 потоком
и копирует исходник в `storage/media/:ownerId/`. Список расширений включает MP3,
WAV, OGG/Opus, FLAC, M4A/AAC, MP4/M4V, WebM, MOV, MKV, AVI, AIFF и WMA.
Тип определяется реальными потоками; прикреплённая обложка MP3 не считается видео.

`inspectFile(path, {signal?})` возвращает кодеки/потоки и `browserCompatible`.
Совместимые MP3, PCM WAV, FLAC, OGG/Opus, M4A AAC, MP4 H.264/yuv420p/AAC
и поддерживаемые WebM остаются без перекодирования. Проверяется и контейнер,
и кодек: расширение `.mp4` само по себе не означает совместимость.

Для несовместимого источника `preparePlayback` создаёт временную M4A (AAC)
или MP4 (H.264/yuv420p и AAC). Уже подходящие дорожки перепаковываются без
перекодирования; остальные преобразуются FFmpeg. Исходник сохраняется отдельным
source с `status=unavailable`, `reason=unsupported_codec`, fileId и URL скачивания.
Копия того же item получает `status=available`, поэтому плеер выбирает её.
Это не означает потерю оригинала: полный экспорт включает оба файла.

FFmpeg запускается массивом аргументов без shell. Анализ ограничен 30 с,
подготовка — 5 мин; обработка stderr ограничена, отмена останавливает процесс,
временный результат удаляется при ошибке и после публикации. Неподготовленный
результат не объявляется доступным источником. Перед повторным использованием
файла сверяются наличие, размер и hash. Загрузка оригинала после metadata-only
переноса восстанавливает байты и прежние item/file ID; запись атомарна через rename.

## Передача и права

`app.ts`: multipart `/api/items/upload`, до 2 ГиБ на файл и 100 файлов в запросе;
MCP выдаёт одноразовую upload-ссылку. Исходное имя файла сохраняется как fallback
после встроенных метаданных; UUID используется только для отдельного tmp-каталога. `/api/items/import-local` и MCP local import
читают только `LOCAL_MEDIA_DIRS`, с проверкой realpath. Оригиналы в этих каталогах
не меняются. Файлы отдаются потоком через авторизованный `/files/:id`, с проверкой
owner, `nosniff`, HTTP Range/206 и корректным 416 для неверного диапазона.
Лимиты скачивания и переноса — в [youtube](youtube.md), [portability](portability.md).

## Как проверить

`media.test.ts` создаёт настоящие файлы FFmpeg: MP3 с обложкой, WAV, MP4,
несовместимый MKV, AAC и MOV. Проверяются кодеки, сохранение encoded packets при
remux, таймаут/отмена и очистка. `library.test.ts` проверяет хэши оригинала/копии,
сохранение item, смешанный audio/video-плейлист, повтор и конкурентный импорт.
`routes.test.ts` проверяет upload, Range и чужие IDs.
`replacement.test.ts` проверяет изоляцию предложений, конфликт YouTube,
локальную загрузку и выбор подготовленной копии с сохранением полей записи.

В браузере нужно отдельно декодировать и перемотать локальные audio/video,
переключить их в одной очереди, скачать оригинал и проверить другой аккаунт.
