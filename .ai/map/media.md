# Медиатека и локальные файлы

Фильтр доступности, пагинация и выбор порядка воспроизведения учитывают
действующие заимствованные источники. Фильтр собственного локального файла
проверяет файлы владельца. Плеер повторно запрашивает права перед началом
воспроизведения или выбором запасного источника для общей записи.

## Код и данные

`apps/server/src/library.ts` содержит `LibraryService`: owner-scoped snapshot,
импорт локального файла/YouTube, названия, теги, правила плейлистов и настройки.
`itemDto` формирует источники со `streamUrl=/files/:fileId`; размер `BigInt`
из Prisma переводится в JSON-число. Схема БД — `apps/server/prisma/schema.prisma`.
Runtime-контракты — `packages/contracts/src/index.ts`.

## Страницы медиатеки

Браузер получает список через `/api/library/page` и сводку через
`/api/library/overview`. Размер страницы — 100. Курсор учитывает владельца,
фильтры и ревизию. SQLite-триггеры обновляют ревизию при изменении каталога.
Запрос `/api/library/ids` обслуживает действия над всей выдачей, а
`/api/library/items` возвращает по ID до 100 записей в запрошенном порядке.
Обработчики и тесты — `apps/server/src/library-pages.ts` и `library-pages.test.ts`.

Сохранённая по ссылке запись принадлежит получателю. `sharing.ts` проверяет
действующие привязки при чтении записи, каталога и плейлиста, добавляет
`ItemDto.shared` и заимствованные источники `SourceDto.shared`. Локальное
проигрывание и обложка используют маршруты `/api/shared-items/` с проверкой
прав. После закрытия доступа у записи остаются теги, избранное и собственные
источники. Создание локальной копии повторно проверяет право по ссылке внутри
транзакции импорта, включая повторное использование файла.

## Каталог, отбор и разметка

Тег принадлежит одному владельцу. В SQLite `name` сохраняет прежний уникальный
ключ, в ответах API и MCP `name` содержит отображаемое имя из `label` с откатом
к прежнему имени. Четыре группы плоские, у источника возможны несколько
родителей. `taxonomy.ts` проверяет принадлежность родителей, уникальность
имени в каждой ветке и циклы при создании или изменении тега. Метки в архиве
сохраняют ID и точные назначения для старых плейлистов и синхронизации.
Обычное редактирование назначений записи сохраняет её архивные связи. Явный
поиск по архивному ID оставляет точную старую выборку. Архивные метки скрыты
в обычном каталоге, счётчиках и текстовом поиске.
Старые плоские метки, отличавшиеся регистром, сохраняют обе идентичности в БД и
в архивах v1. Флаг `legacyFlat` сохраняется при импорте и повторном экспорте.
При создании, перемещении и переименовании действуют правила уникальности нового каталога.

Страницы, все ID и поиск MCP используют один SQL-отбор. Параметр `tagMode`
выбирает И (по умолчанию) или ИЛИ для всех выбранных меток. Предки находятся
по рекурсивной выборке SQLite, общие потомки учитываются однократно.
`performanceFilter` принимает ost, male, female или vocal. Пустое значение
оставляет все исполнения, vocal включает записи с ещё не указанным голосом.
Первая страница возвращает `tagCounts` с учётом текста и верхних фильтров.
Поиск понимает псевдонимы и имена предков. Доступ к заметкам при поиске
ограничен сессией браузера.

`missingGroup` фильтрует по одной причине (source, artist, genre, mood,
performance, voice), а `needsClassification` выбирает все неполные записи.
В `PATCH /api/items/:id` и `POST /api/items/batch` значение
`completeClassification: true` требует полного набора. Пакет может передать
`expectedRevision` из сводки для проверки актуальности предпросмотра.
Изменения применяются одной транзакцией. Выбор OST очищает прежние голоса.

## Обложки аудио

`artwork.ts`: авторизованный `/api/items/:id/artwork` извлекает embedded cover
из локального audio source, в том числе аудиокопии YouTube/video item. DTO вычисляет
source.thumbnail для такого источника; URL не записывается в БД/manifest. Если
дериватив потерял cover, endpoint сначала проверяет сохранённый оригинал.
Полный перенос оригиналов сохраняет обложки без новых моделей/миграций.

JPEG/PNG/WebP распознаются по сигнатуре, результат до 5 МиБ. Общий бюджет чтения
метаданных — 8 МиБ и 4096 операций tokenizer, отдельная allocation ограничена;
большие audio/free boxes пропускаются через seek, не расходуя read budget.
Это ограничивает также множество FLAC PICTURE blocks, не только одну обложку.
Много метаданных, отсутствие/ошибка cover дают 404 и fallback в плеере.
Кэш оригиналов хранит до восьми результатов, проверка owner/item/file и наличия/mtime оригинала
на каждом запросе. Ответ private,no-cache, Vary Cookie/Authorization, nosniff.
`strtok3` — прямой dependency для ограниченного file tokenizer.

Для списка, мини-плеера и строк очереди `?size=thumb` возвращает WebP
до 96×96 и 32 КиБ. Кэш хранит до 512 результатов, включая отсутствие обложки.
Одновременно обрабатываются до двух миниатюр. ETag поддерживает повторный
запрос с проверкой сессии. Для YouTube используется стандартная миниатюра 120×90.
Большая сцена плеера запрашивает оригинал. Для каталога плейлистов и крупной обложки по ссылке служит `?size=cover` (WebP до 640×640 и 768 КиБ, без увеличения исходника). До 32 результатов кешируются, одновременно конвертируется одна крупная обложка. На страницах по ссылке применяются те же проверки доступа, что для исходной обложки. При ограничении тяжёлых операций Kaname отдаётся исходное изображение. Для крупной обложки YouTube используются sddefault и запасной hqdefault. Старые адреса миниатюр в сохранённой сводке нормализуются при чтении.

Item сохраняет собственное `title`, `originalTitle`, kind audio/video и связи.
Недоступность относится к source и не удаляет item. Обновление YouTube сохраняет
переименованное пользователем название и теги. При регистрации создаются шесть типов происхождения, четыре настроения и
метки Cover, Remix, «Опенинг» и «Эндинг». «Избранное» хранится у записи.

YouTube узнаётся по owner/provider/videoId, файл — по owner/SHA-256.
`importLocal(..., {itemId})` добавляет источники к существующему item без замены
его названия и ID. Одинаковый файл допускается у разных items как отдельная связь;
физическая копия внутри owner переиспользуется. Два одновременных обычных импорта
одного файла повторно проверяют источник внутри транзакции и не создают лишний item.
YouTube upsert также повторно проверяет идентичность внутри транзакции.
Удаление item/тега/плейлиста с явными зависимостями в правилах запрещено.
При удалении item его ordering-ссылки manualOrder и обе очереди очищаются
транзакционно; позиция текущего оставшегося item сохраняется. setSettings
нормализует queue/originalQueue и текущий индекс по исходному ID.

## Замена источника

`replacement.ts` проверяет новый источник в карточке записи. Превью показывает его
название и длительность при наличии. Для YouTube сервер проверяет метаданные
конкретного ролика, а доступность во встроенном плеере выясняется при запуске.
Ссылка, уже привязанная к другой записи владельца, вызывает конфликт.

Подтверждение добавляет источник к тому же Item и записывает
`preferredSourceId`, сохраняя поля записи, включая её длительность, и прежние
связи. Для несовместимого локального файла предпочтительной становится
подготовленная копия. Новое предпочтение действует со следующего запуска.
Предложение агента содержит ссылку и объяснение. Для его проверки, применения
и отклонения требуется вход в Hibiki через браузер.

Файл превью находится в `storage/uploads/replacements/` до подтверждения или
отклонения. Сервер удаляет временный файл после обработки и периодически
очищает оставленные загрузки старше суток.

## Импорт и совместимость

`media.ts` анализирует файл через music-metadata и FFmpeg, считает SHA-256 потоком
и копирует исходник в `storage/media/:ownerId/`. Список расширений включает MP3,
WAV, OGG/Opus, FLAC, M4A/AAC, MP4/M4V, WebM, MOV, MKV, AVI, AIFF и WMA.
Тип определяется реальными потоками; прикреплённая обложка MP3 не считается видео.

`inspectFile(path, {signal?})` возвращает кодеки/потоки, наличие звуковой дорожки
и `browserCompatible`. Для локального файла признак сохраняется в `MediaFile.hasAudio`
и виден в `SourceDto.hasAudio`. Worker при старте заполняет пропуски ограниченными
пакетами и последовательно проверяет FFmpeg-заголовки прежних файлов. Медиатека
отдаётся независимо от этой проверки. У недоступных для проверки файлов и
YouTube признак может отсутствовать.
Совместимые MP3, PCM WAV, FLAC, OGG/Opus, M4A AAC, MP4 H.264/yuv420p/AAC
и поддерживаемые WebM остаются без перекодирования. Проверяется и контейнер,
и кодек: расширение `.mp4` само по себе не означает совместимость.

Подготовка совместимого звука сохраняет кодированные пакеты, включая HE-AAC.
Если новый источник требует декодирования, звуковая дорожка записывается во FLAC
с исходной частотой и количеством каналов. Для декодируемых float32 сохраняются
плавающие отсчёты в PCM WAV или в MOV с видео H.264. Исходный файл хранится отдельным
источником с причиной `unsupported_codec`. Полный экспорт включает оригинал.
Установленные файлы сохраняют существующее качество.

FFmpeg запускается массивом аргументов без shell. Анализ ограничен 30 с,
подготовка — 5 мин; обработка stderr ограничена, отмена останавливает процесс,
временный результат удаляется при ошибке и после публикации. Неподготовленный
результат не объявляется доступным источником. Перед повторным использованием
файла сверяются наличие, размер и hash. Загрузка оригинала после metadata-only
переноса восстанавливает байты и прежние item/file ID; запись атомарна через rename.

## Передача и права

`app.ts`: multipart `/api/items/upload`, до 2 ГиБ на файл и 100 файлов в запросе;
MCP выдаёт одноразовую upload-ссылку. Исходное имя файла сохраняется как fallback
после встроенных метаданных; UUID используется только для отдельного tmp-каталога. `/api/items/import-local` и MCP local import
читают только `LOCAL_MEDIA_DIRS`, с проверкой realpath. Оригиналы в этих каталогах
не меняются. Файлы отдаются потоком через авторизованный `/files/:id`, с проверкой
owner, `nosniff`, HTTP Range/206 и корректным 416 для неверного диапазона.
У полученной записи в смешанном плейлисте адрес потока и обложки относится к
ссылке составителя или сохранённому плейлисту. Каждый новый запрос требует
действующего доступа по обеим ссылкам. Включение разрешения на исходной ссылке
не копирует файлы и не занимает дополнительную квоту.
Лимиты скачивания и переноса — в [youtube](youtube.md), [portability](portability.md).

## Загрузка при воспроизведении

В звуковом режиме ретранслятор вкладки принимает файлы до 128 МиБ. Вначале
запрашиваются примерно десять секунд звука и при необходимости страница с индексом
в конце M4A. Если известное смещение первого MPEG-кадра не меньше 64 КиБ,
плеер сразу передаёт кадры декодеру. Встроенная обложка ID3 догружается в память
вкладки после звуковых данных. Полный кеш совпадает с оригиналом побайтно.
Оставшийся звук поступает непрерывным Range-ответом с низким приоритетом. После полного
набора текущего файла плеер готовит начало следующего. В режиме без ретранслятора
работает обычное воспроизведение через Range. YouTube IFrame управляет своей загрузкой.

В WebKit с поддержкой MediaSource плеер подаёт M4A в декодер из тех же уже
полученных диапазонов. Для AAC с индексом в конце вкладка переносит `moov`
перед `mdat` и пересчитывает `stco` или `co64` в копии заголовка.
При несовместимой структуре или перемотке за пределы буфера декодера плеер
продолжает с выбранной позиции через Range. Обе ветки используют общую проверку прав.

Для MP4 с дорожкой AAC, Opus или FLAC сервер строит виртуальный аудиофайл MP4. Заголовок и
таблица смещений находятся в кеше процесса, звуковые пакеты читаются из оригинала.
Адрес `/files/:id/audio` поддерживает HEAD и Range. Для общих записей действуют
адреса и проверки доступа соответствующей ссылки. Файлы обложек размеров
`thumb` и `cover` хранятся отдельно в `storage/cache/artwork`. Версия в адресе
локальной обложки зависит от хешей источников записи.

## Как проверить

`media.test.ts` создаёт настоящие файлы FFmpeg: MP3 с обложкой, WAV, MP4,
несовместимый MKV, AAC и MOV. Проверяются кодеки, сохранение encoded packets при
remux, таймаут/отмена и очистка. `library.test.ts` проверяет хэши оригинала/копии,
сохранение item, смешанный audio/video-плейлист, повтор и конкурентный импорт.
`routes.test.ts` проверяет upload, Range и чужие IDs.
`replacement.test.ts` проверяет изоляцию предложений, конфликт YouTube,
локальную загрузку и выбор подготовленной копии с сохранением полей записи.

В браузере нужно отдельно декодировать и перемотать локальные audio/video,
переключить их в одной очереди, скачать оригинал и проверить другой аккаунт.

При включении Kaname квоты берутся из назначения Hibiki. Все пути создания записей проверяют остаток внутри транзакции публикации. Копирование и чтение больших файлов проходят до транзакции. Потоки загрузки, распаковки и записи резервируют место в общей SQLite. Для пользователя и администратора типовая квота равна 1 000 000 000 байтов. Проверка заголовков медиа разрешена, скачивание и перекодирование требуют разрешения владельца. Пользователь загружает поддерживаемые браузером файлы и добавляет ссылки. Импорт из каталогов сервера доступен владельцу.

## Качество звука

Исходное качество трека обязательно на всём пути от получения до воспроизведения. Для ускорения допустимы оптимизация запросов, кеш, буферизация, предзагрузка и отдельные размеры обложек. Понижение битрейта, частоты дискретизации, разрядности, числа каналов или перекодирование с потерями ради оптимизации запрещены при любых условиях.
