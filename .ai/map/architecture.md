# Архитектура

## Текущее состояние

Реализации нет. Есть [техническое предложение](../features/01-mvp/tech.md).

## Предлагаемые границы

- Сайт и MCP → общие доменные сервисы → SQLite и файловое хранилище.
- Отдельный worker → та же долговечная очередь заданий в SQLite и storage.
- Ядро правил плейлистов не знает HTTP, MCP, React и способ загрузки файла.
- Провайдер YouTube и local media — адаптеры источников постоянного item.
- Предполагаемые приложения: `apps/web`, `apps/server`, `apps/worker`;
  общие пакеты: `packages/contracts`, `packages/core`. Этих путей ещё нет.
- Один сервер отдаёт собранный сайт, API, авторизованные файлы и MCP.

Права и владение проверяются в сервисах независимо от клиента. Нагрузка локальная;
микросервисы и внешний брокер в первой итерации не требуются.

## Как проверить после реализации

Один сценарий через UI и MCP даёт одинаковый результат. Пользователь не читает
и не меняет чужие данные. Сервер и worker используют одни контракты заданий.
