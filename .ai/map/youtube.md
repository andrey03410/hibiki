# YouTube

## Адаптер и окружение

`apps/server/src/youtube.ts`: нормализация ссылок, метаданные/состав через yt-dlp,
oEmbed для отдельного видео, refresh, скачивание и диагностика. Разрешены только
поддержанные адреса youtube.com/youtu.be, включая music/mobile, shorts/embed/live;
логин, пароль, произвольный host/port и другие протоколы отвергаются.
Задания и публикация результата — [jobs](jobs.md), [media](media.md).

Нужен актуальный yt-dlp с EJS и поддерживаемым JS runtime. FFmpeg поставляется
через `ffmpeg-static`. Настройки читаются из окружения:

| Переменная | Поведение |
|---|---|
| `YTDLP_PATH` | Бинарник; по умолчанию `yt-dlp` из PATH |
| `YTDLP_JS_RUNTIME` | Значение `--js-runtimes`; по умолчанию текущий Node |
| `YTDLP_REMOTE_EJS=1` | Разрешить получение компонента EJS с GitHub |
| `YTDLP_PROXY` | Необязательный прокси для yt-dlp |
| `YTDLP_ALLOW_UPDATE=1` | Разрешить явную команду обновления инструмента |

Диагностика: `npx tsx --env-file-if-exists=.env apps/worker/src/main.ts --diagnostics`.
Обновление: та же команда с `--update-ytdlp`, только при `YTDLP_ALLOW_UPDATE=1`.
Само приложение не включает автоматическое обновление. Standalone-сборка yt-dlp
может содержать EJS; для других установок требуется соответствующий компонент.

Прокси и маршрутизация принадлежат окружению конкретной машины. Личные адреса,
реквизиты и пути не фиксируются в публичных документах. Ошибки провайдера редактируют
значение прокси перед сохранением в отчёт.

## Поведение и ограничения

Импорт single/playlist создаёт отдельный item для каждой распознанной позиции,
сохраняет ID недоступных позиций и не скачивает медиа автоматически. Разовый состав
ограничен `--playlist-end 10000`; повтор узнаёт существующие YouTube IDs владельца.
Flat metadata может быть неполной. Ошибки отдельных позиций попадают в отчёт,
удачные позиции остаются. Автосинхронизации состава и OAuth приватных библиотек нет.

Если single-video metadata не получены через yt-dlp, возможен fallback к официальному
YouTube oEmbed. Он сохраняет название/thumbnail и предупреждение: возможность
встраивания и скачивания этим не проверяется. Для плейлиста fallback не подменяет
получение состава. Сетевая ошибка сама по себе не отмечает item удалённым;
refresh меняет доступность source при распознанном ответе о недоступности.

Скачивание audio/video добавляет local sources того же item. Для видео запрашивается
H.264 до 1080p/AAC с fallback и MP4, для audio — M4A. yt-dlp получает
`--max-filesize=4 GiB`; локальная публикация дополнительно проверяет формат
и при необходимости готовит браузерную копию. Исходники не удаляются.

Процессы запускаются без shell, с отменой всей группы. Обычный вызов ограничен
120 с, скачивание — часом; socket timeout 20 с, два повтора, stdout до 32 MiB,
stderr ограничен. oEmbed — 15 с и ответ до 128 KiB.

Встроенный видимый YouTube IFrame — отдельный путь воспроизведения. Запрет
встраивания, региональные ограничения, проверки провайдера и сеть могут помешать.
Скрытый iframe для гарантированного фонового звука не используется. Наличие
yt-dlp не снимает ограничения провайдера и не гарантирует скачивание недоступного видео.

## Как проверить

`youtube.test.ts` проверяет нормализацию, переменную структуру metadata,
недоступные позиции и oEmbed fallback. `jobs.test.ts` — отмену реального дочернего
процесса, частичный результат, повтор и сохранение item. В живой проверке нужны настоящий плейлист, повтор без
дублей, реальный download/decode/seek, refresh и ошибки IFrame. Тестовая реализация
провайдера не доказывает доступность YouTube с текущей машины.
