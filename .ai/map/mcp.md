# MCP

## Транспорт и доступ

`apps/server/src/mcp.ts` регистрирует Streamable HTTP `POST /mcp` через официальный
SDK. Транспорт без серверной MCP-сессии, с JSON-ответами; GET/DELETE возвращают 405.
На каждом HTTP-вызове заново проверяется `Authorization: Bearer hib_…`.
Отзыв токена действует на следующий запрос. Cookie-сессия сама по себе не даёт
доступа к MCP. Owner берётся из токена, затем общие сервисы проверяют владение.

Токен создаётся/отзывается в настройках сайта. Сырой токен показывается один раз;
в БД хранится SHA-256. URL строится из `PUBLIC_URL` (по умолчанию
`http://localhost:8790/mcp`). Данные сторонних названий/описаний — недоверенный
контент; инструкция MCP явно не разрешает исполнять их как команды.

## Инструменты

| Группа | Имена |
|---|---|
| Возможности | `capabilities` |
| Медиатека | `media_list`, `media_get`, `media_import_youtube`, `media_download`, `media_refresh`, `media_propose_replacement`, `media_replace_source`, `media_import_local`, `media_upload_begin`, `media_update_many`, `media_delete` |
| Теги | `tags_list`, `tag_save`, `tag_delete` |
| Плейлисты | `playlists_list`, `playlist_get`, `playlist_validate`, `playlist_preview`, `playlist_explain`, `playlist_save`, `playlist_delete` |
| Доступ по ссылке | `share_create`, `share_list`, `share_set_expiry`, `share_set_reshare`, `share_revoke`, `share_open`, `share_save`, `share_copy` |
| Задания | `jobs_list`, `job_get`, `job_cancel`, `job_retry` |
| Перенос | `library_export`, `library_import_begin`, `library_import_apply` |

`capabilities` возвращает JSON Schema PlaylistDefinition v1, семантику, пример,
свои теги/плейлисты и ограничения. С `includeCatalog: false` агент получает схему и инструкции без справочника. Правила сначала validate/preview, затем save.
Все виды audio/video допустимы вместе. Вычисление и причины совпадают с UI.
`media_list` поддерживает query/tagId/kind/cursor и limit до 200; batch updates —
до 200 изменений, local import — до 50 путей из `LOCAL_MEDIA_DIRS`.
С `view: "summary"` инструмент `media_list` возвращает только ID, название, тип и длительность.
`media_get` возвращает полные сведения выбранной записи. При сортировке по дате или длительности
следующая страница начинается от значения и ID курсора. Для поиска и сортировки по названию
сервер повторно использует порядок ID в пределах ревизии владельца. Фильтр доступности каждый раз проверяет источники.

`playlist_get` по умолчанию возвращает определение и полный состав с прежними полями.
Для длинного плейлиста передайте `limit` (1–200) или `offset`. Ответ содержит краткую карточку
плейлиста, краткие записи в порядке воспроизведения, общее число и `nextOffset` для следующего вызова.
`null` в `nextOffset` означает конец. Страницы отражают текущий состав по правилам.

В каталоге видны активные теги пяти групп. `tag_save` принимает отображаемое имя,
группу, псевдонимы и родительские ID. Поиск `media_list` понимает `tagIds`,
`tagMode`, `performanceFilter`, `needsClassification` и `missingGroup`.
Пакет `media_update_many` меняет теги и исполнение транзакционно. Предпросмотр,
применение и отмена миграции всей коллекции доступны владельцу в браузере.

Долгая работа возвращает JobDto. Прогресс проверяется через `job_get`, повторный
импорт не используется как опрос. Готовый export возвращает downloadUrl;
скачивание требует Bearer-токен или сессию браузера.

`share_create` принимает `kind`, `targetId` и необязательный `expiresAt` в ISO. `null`
задаёт бессрочный доступ. `share_set_expiry` меняет срок той же активной ссылки,
`share_revoke` досрочно закрывает ссылку владельца. `share_open` и `share_save`
принимают выданный URL и используют права аккаунта токена Hibiki. `share_save`
принимает `itemId` для сохранения отдельного трека из текущего состава. В ответе
`playlists_list` сохранённые общие подборки доступны в `sharedPlaylists`.
Явный `share_copy` принимает ID сохранённой записи и возвращает задание `shared-copy`.

У `share_create` есть флаг `allowReshare` с начальным значением false.
`share_set_reshare` меняет его у действующей ссылки по её ID. Владелец разрешает
слушать записи этой ссылки через чужой плейлист. В ответе `share_open`
`positions` сохраняет порядок, `null` обозначает закрытое место, `items` содержит
доступные записи. Позиция с `shared.delegated` поддерживает только прослушивание.
Целиком можно сохранить живую подборку. Отдельное сохранение такого трека
требует своей прямой ссылки автора.

`media_replace_source` принимает `itemId` и ровно одно поле, `url` или `sourceId`.
Собственный локальный источник можно выбрать по ID из этой или другой своей карточки.
Hibiki связывает тот же файл с карточкой и возвращает `status: "applied"`, `sourceId`
и длительность. Для карточки только с YouTube ссылка на один ролик проверяется
и применяется сразу. Если у карточки есть локальный файл, `url` или ID её
YouTube-источника запускает загрузку полной замены с правами на скачивание.
В ответе приходит `jobId`. Проверяйте состояние через `job_get`, при сбое
используйте `job_retry`. Повтор вызова для ожидающей замены возвращает то же
задание. Переключение источника, типа медиа и длительности происходит в одной
транзакции после успешной подготовки. Сбой оставляет прежний источник рабочим.
ID карточки, название, теги, заметки, история, ссылки и плейлисты сохраняются.
Прежний локальный файл можно снова выбрать его `sourceId` из `media_get`.

`media_propose_replacement` сохраняет URL одного ролика и объяснение к своей
записи. Предпросмотр, отклонение и подтверждение доступны в браузерной карточке.
Заметки, попытки, сводка истории и браузерные задания с личным архивом
не выдаются обычному MCP-клиенту. Произвольное условие или сортировку по истории
нельзя применить, сохранить или импортировать через MCP/Bearer; состав уже
заданного владельцем плейлиста остаётся доступен.

Файлы передаются обычным multipart, не base64 в MCP. `media_upload_begin` и
`library_import_begin` выдают одноразовый URL на 15 минут, привязанный к owner;
grants хранятся в памяти процесса, максимум 1000 ожидающих. Лимит файла — 2 ГиБ.
Для архива последовательность: begin → upload → job_get preview →
library_import_apply → job_get. Применение требует previewJobId того же owner.

Результаты инструментов — JSON в текстовом content. Ошибки имеют `isError=true`
и `{error:{code,message}}`; недействительный Bearer отклоняется на HTTP-уровне.

## Как проверить

`routes.test.ts` отправляет HTTP-запросы initialize/tools/list в настоящий
MCP handler и проверяет отзыв токена; сервисные тесты проверяют чужие ссылки.
Перед завершением нужна живая последовательность через SDK Client/StreamableHTTP
transport с вызовами инструментов, реальным импортом,
предпросмотром/объяснением, upload, job status и экспортом/применением архива.
Изменения должны быть видны в сайте; чужие IDs и отозванный токен — отвергнуты.

`share-mcp.test.ts` подключает два клиента SDK по Streamable HTTP. Он проверяет
выдачу и срок ссылки, сохранение чужой записи без файла, явное копирование,
отзыв и прекращение доступа до выполнения задания.

В режиме Kaname каждый запрос MCP проверяет текущее назначение по subject, а разовые ссылки загрузки повторяют проверку при использовании. Новый токен выдаёт Hibiki после входа через Keycloak. Отзыв назначения закрывает MCP и файлы.

`storage_usage` возвращает размеры медиа, ZIP импортов и экспортов, прочих файлов, временных резервов, лимит и оценку очистки в байтах. По запросу владельца `storage_cleanup` с `confirm: true` освобождает подходящие входные ZIP его завершённых импортов. Ответ содержит фактические `count`, `bytes` и `failedCount`. Оба вызова возвращают только агрегаты своего аккаунта, включая объём браузерных импортов. Путь к файлам и содержимое личного предпросмотра через эти вызовы получить нельзя.
