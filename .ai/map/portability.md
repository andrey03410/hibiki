# Перенос библиотеки

## Формат и операции

`apps/server/src/portability.ts`: `exportLibrary`, `inspectArchive`, `applyArchive`.
Задания [jobs](jobs.md) обеспечивают отдельные preview/apply и download.
ZIP содержит `manifest.json` с `format:'hibiki', version:1`, origin, items/sources,
теги, правила/порядок плейлистов, поддерживаемые настройки плеера и описание файлов.
Медиа включаются по `includeFiles`; пароли, сессии и MCP-токены не экспортируются.

Экспорт получает короткий снимок БД, затем потоково считает SHA-256 и пишет ZIP
через yazl во временный `.part` с последующим rename. Все файлы, связанные через
sources, включаются независимо от available/unavailable: оригинал несовместимого
кодека и браузерная копия сохраняются вместе. Числа bytes из Prisma BigInt
переводятся в JSON numbers. Медиа кладутся без сжатия ZIP.

`inspectArchive` через yauzl потоково распаковывает в каталог задания. Проверяются
версия/строгие схемы, уникальность IDs и путей, все ссылки, граф и циклы плейлистов,
размер и SHA-256 каждого файла. Содержимое медиа анализируется `inspectFile`;
MIME из allowlist и kind должны совпасть с действительным файлом. Исполняемые/HTML
данные с поддельным MIME не публикуются. Несовместимый оригинал остаётся unavailable
с `unsupported_codec`, даже если манифест объявлял его доступным.

Preview показывает counts, missingFiles, issues и совпадения с целевой библиотекой.
Применение требует подтверждённый preview и неизменный hash архива, повторяет
проверки и только затем изменяет целевой аккаунт. Большие файлы копируются до
транзакции; при ошибке новые копии убираются. В транзакции переносятся строки,
настройки и связи с переназначением owner/IDs.

## Совпадения и отсутствующие файлы

ID сопоставляются детерминированно по origin/owner/типу/исходному ID; ссылки правил,
manualOrder, queue и originalQueue переписываются. Теги сопоставляются по имени,
YouTube — по videoId; локальный hash используется с учётом границ отдельных items.
Два items с общим файлом не должны молча превращаться в один. Конфликт нескольких
YouTube-источников с разными целевыми items блокирует применение.

При совпадении существующие собственные названия/плейлисты сохраняются;
preview сообщает о различиях. Повтор того же импорта переиспользует записи.
Метаданные без файлов создают недоступные local sources и сохраняют file/hash-связь.
Следующий полный импорт может восстановить их без дублей; уже имеющийся пригодный
файл owner может переиспользоваться. Статус `unsupported_codec` оригинала при
переносе не превращается в available. Источник отсутствующего файла получает причину
«Локальный файл не включён в архив».

## Бюджеты и безопасность

- Внутренний входной ZIP и суммарный распакованный размер ограничены 20 ГиБ.
- Каждый файл манифеста/архива — до 4 ГиБ; manifest — до 16 МиБ.
- До 100 001 ZIP-entry; до 100 000 items/files, 10 000 тегов/плейлистов.
- Разрешены только `manifest.json` и плоские `files/:name`; запрещены traversal,
  абсолютные пути, symlink, повторы, лишние файлы и опасная степень сжатия.
- Для HTTP/MCP archive upload применяется отдельный лимит 20 ГиБ; обычный
  media upload ограничен 2 ГиБ. Политика `upload-policy.ts` используется обоими
  путями загрузки; MCP capabilities/upload grants сообщают правильный maxBytes.

Архив не исполняет код и не пишет за пределы storage. Проверка/хэширование
отменяются через AbortSignal. Экспорт библиотеки не является согласованным бэкапом
всего инстанса: для него отдельно нужны SQLite и storage. Экспорт ссылок
не восстанавливает удалённое видео без сохранённого медиафайла.

## Как проверить

`portability.test.ts` покрывает реальный ZIP, hash/path/MIME-проверки,
metadata-only → full import, повтор, сохранение нескольких sources/общего файла,
переназначение owner, неверные версии и ссылки. Вживую экспортировать смешанную библиотеку, импортировать
в другой аккаунт и чистую установку через preview/apply; сравнить хэши оригинала
и копии, теги, состав/порядок, queue и положение плеера. Подмена архива после
preview должна отклоняться. Исходная библиотека остаётся прежней.
