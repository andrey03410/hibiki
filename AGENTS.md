# Hibiki — вход для агентов

**Hibiki** (響き, «звучание, отзвук») — личная медиатека с гибкими составными
плейлистами, изначально удобная для внешних ИИ-агентов. У каждого пользователя
свой пул аудио и видео, теги и плейлисты. Видение — в [`.ai/vision.md`](.ai/vision.md).

## Текущее состояние

Репозиторий содержит только документы и основу рабочего процесса.
Приложение, зависимости, БД, MCP и команды запуска **ещё не созданы**.
Первая задача — [01-mvp](.ai/features/01-mvp/README.md), стадия `product`.
Продукт и техника записаны как предложения; реализация ждёт сигнала владельца.

Последняя инструкция владельца: «Пока только занеси туда слой знаний и только
буквально основу репы без реализации» и «потом по сигналу реализация».
Не создавать приложение, устанавливать зависимости или запускать реализацию,
пока владелец не даст этот сигнал. Это ограничение относится к текущему заказу,
а не ко всем будущим задачам.

## Предлагаемый стек и проверки

TypeScript · Node.js LTS · npm workspaces · Fastify · SQLite + Prisma 7 ·
React + Vite + React Router · Zod 4 · MCP Streamable HTTP · yt-dlp · FFmpeg/FFprobe.

После появления кода обязательная тройка, именно в этом порядке:
`npm test` → `npm run build` → `npx tsc --noEmit`.
Сейчас этих команд нет. Для документов проверяются ссылки, пути и структура.
Команды запуска, порты и переменные фиксируются в [dev-env](.ai/map/dev-env.md)
при реализации; не выдавать предполагаемые команды за существующие.

## Как ведём задачи

Как в Asobiba и Douga: бриф → продукт (если нужен) → техника → план →
реализация и QG → проверка владельцем → вливание через PR.
Скилл [feature](.claude/skills/feature/SKILL.md), папка задачи
`.ai/features/NN-slug/`, статус во frontmatter её `README.md`.

Гейты — явные ответы владельца. После плана отдельного гейта нет.
Прямой сигнал «реализация» после обсуждения этих документов разрешает перейти
к плану и коду в согласованном объёме; повторно спрашивать то же разрешение не надо.
**Без «принято» или «вливай» PR не вливать.** Исключение — автономный режим,
явно разрешённый владельцем для конкретной задачи.

Первая инициализация этого репозитория сделана напрямую в `main` по поручению
владельца. Следующие изменения — в ветках `codex/NN-slug` через обычный процесс.

## Скиллы

`.claude/skills/` — источник, `.agents/skills` — симлинк для Codex.
`CLAUDE.md` — симлинк на этот файл. При совпадении с запросом читай скилл целиком.

| Скилл | Когда |
|---|---|
| [feature](.claude/skills/feature/SKILL.md) | Новый бриф, статус, продолжение задачи, подтверждение стадии |
| [verify](.claude/skills/verify/SKILL.md) | QG, проверки, перед коммитом или PR |

Superpowers можно использовать внутри стадий. Его артефакты живут в папке задачи,
а не в `docs/superpowers/`.

## Правила

- Доки и общение — по-русски; код, идентификаторы и conventional-коммиты — по-английски.
- ИИ-материалы — только в `.ai/`, этом файле и скиллах рабочего процесса.
  Новый тип материалов — новая подпапка и строка в `.ai/README.md`.
- Изменил поведение зоны — обнови её карточку в той же ветке. Влитые задачи — архив.
- Не объявляй готовность по типам и юнитам: нужна свежая тройка и проверка затронутой
  поверхности — браузер, настоящий MCP, медиа, задания, перенос между аккаунтами.
- `.env`, `storage/`, БД, пароли, токены и пользовательские медиа не коммитить.
  Репозиторий публичный по указанию владельца. Проверочные аккаунты и доказательства
  держать в `storage/`.
- У каждого item постоянная идентичность; ссылка и локальный файл — его источники.
  Недоступность YouTube не удаляет item, собственное название, теги и связи.
- Правила плейлистов — данные по версионированной схеме. Произвольный код и SQL
  из пользовательского конфига не исполняются. Циклы зависимостей запрещены.
- Сайт и MCP используют одни сервисы; права и владение проверяются на каждой операции.
- Агент — внешний клиент MCP. Встроенная LLM и ключи провайдеров в MVP не нужны.
- Нагрузка небольшая, сервис локальный. Микросервисы, Redis и облачные хранилища
  не добавлять без конкретной необходимости.
