# Hibiki — вход для агентов

**Hibiki** (響き, «звучание, отзвук») — личная медиатека с гибкими составными
плейлистами, изначально удобная для внешних ИИ-агентов. У каждого пользователя
свой пул аудио и видео, теги и плейлисты. Видение — в [`.ai/vision.md`](.ai/vision.md).

## Текущее состояние

Первая итерация — [01-mvp](.ai/features/01-mvp/README.md), [PR #1](https://github.com/andrey03410/hibiki/pull/1).
Выполнена автономно по разрешению владельца: медиатека, mixed player, правила,
MCP, worker и перенос. Проверки — в verify.md задачи. Влитая задача — архив;
новые изменения ведутся отдельной задачей, автономность на них не переносится.

[02. Большой плеер и реальные плейлисты](.ai/features/02-watch-playlists/README.md):

проверка метаданных YouTube-позиций без названия. Статус и QG — в папке задачи.

[04. Медиатека и режимы воспроизведения](.ai/features/04-library-playback-modes/README.md):

быстрые фильтры и компактные карточки.

[05. Перемотка и очередь в мини-плеере](.ai/features/05-compact-player-controls/README.md):
общая шкала, компактная очередь и действия со значками в карточках.

[06. Навигация по медиатеке и управление очередью](.ai/features/06-library-navigation/README.md):

[08. Прослушивание и прокрутка медиатеки](.ai/features/08-library-listening/README.md) — звуковой запуск, видео из мини-плеера, компактные обложки, меню тегов и выдача по 100 записей.

[09. Навигация по тегам](.ai/features/09-library-tag-navigation/README.md) — панель медиатеки, группы тегов, псевдонимы, исполнение и перенос коллекции.

[11. Запуск и управление воспроизведением](.ai/features/11-player-feedback/README.md) — быстрый старт из медиатеки, управление с клавиатуры и мыши, громкость и буферизация, плавная шкала и счётчики плейлистов.

[12. Обложки и быстрый запуск плейлистов](.ai/features/12-playlist-loading/README.md) — обложки в каталоге и компактный ответ для старта очереди.

[13. Записи и плейлисты по ссылке](.ai/features/13-media-sharing/README.md) — живые общие плейлисты, срок и отзыв ссылок, сохранение без файлов и явное копирование через сайт и MCP.

## Стек и проверки

TypeScript · Node.js >=22.16 · npm workspaces · Fastify 5 · SQLite + Prisma 7 ·
React 19 + Vite + React Router · Zod 4 · MCP Streamable HTTP · yt-dlp · FFmpeg.

`npm install` → `npm run db:deploy` → `npm run build` → `npm start`.
Сервер на :8790 отдаёт сайт/API/MCP/файлы; отдельный worker выполняет задания.
`npm run dev` дополнительно запускает Vite на :5174. Перед запуском проверь порты,
см. [dev-env](.ai/map/dev-env.md). Секреты/проверочные данные только в storage и .env.

Обязательная тройка после последних правок, строго по порядку:
`npm test` → `npm run build` → `npx tsc --noEmit`.
Затем живые проверки по [verify](.claude/skills/verify/SKILL.md).

## Как ведём задачи

Как в Asobiba и Douga: бриф → продукт (если нужен) → техника → план →
реализация и QG → проверка владельцем → вливание через PR.
Скилл [feature](.claude/skills/feature/SKILL.md), папка задачи
`.ai/features/NN-slug/`, статус во frontmatter её `README.md`.

Гейты — явные ответы владельца. После плана отдельного гейта нет.
Прямой сигнал «реализация» после обсуждения этих документов разрешает перейти
к плану и коду в согласованном объёме; повторно спрашивать то же разрешение не надо.
**Без «принято» или «вливай» PR не вливать.** Исключение — автономный режим,
явно разрешённый владельцем для конкретной задачи.

Первая инициализация этого репозитория сделана напрямую в `main` по поручению
владельца. Следующие изменения — в ветках `codex/NN-slug` через обычный процесс.

## Правила

- Доки и общение — по-русски; код, идентификаторы и conventional-коммиты — по-английски.
- ИИ-материалы — только в `.ai/`, этом файле и скиллах рабочего процесса.
  Новый тип материалов — новая подпапка и строка в `.ai/README.md`.
- Изменил поведение зоны — обнови её карточку в той же ветке. Влитые задачи — архив.
- Не объявляй готовность по типам и юнитам: нужна свежая тройка и проверка затронутой
  поверхности — браузер, настоящий MCP, медиа, задания, перенос между аккаунтами.
- `.env`, `storage/`, БД, пароли, токены и пользовательские медиа не коммитить.
  Репозиторий публичный по указанию владельца. Проверочные аккаунты и доказательства
  держать в `storage/`.
- У каждого item постоянная идентичность; ссылка и локальный файл — его источники.
  Недоступность YouTube не удаляет item, собственное название, теги и связи.
- Правила плейлистов — данные по версионированной схеме. Произвольный код и SQL
  из пользовательского конфига не исполняются. Циклы зависимостей запрещены.
- Сайт и MCP используют одни сервисы; права и владение проверяются на каждой операции.
- Агент — внешний клиент MCP. Встроенная LLM и ключи провайдеров в MVP не нужны.
- Нагрузка небольшая, сервис локальный. Микросервисы, Redis и облачные хранилища
  не добавлять без конкретной необходимости.
