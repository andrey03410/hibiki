# verify — QG и живая проверка Hibiki

Процесс Asobiba/Douga: свежая тройка после последних правок плюс проверка
реальной затронутой поверхности. Готовность по одним типам/юнитам не объявляется.

## 1. Зоны и фактическое состояние

Проверь diff относительно main, незакоммиченные и новые файлы, затем соответствующие
карточки [карты](../../../.ai/map/README.md). Для начального репозитория без родителя
проверь staged-файлы и весь состав дерева.

Если изменены только документы и служебная основа (например gitignore/editorconfig),
проверь локальные ссылки, пути, симлинки, frontmatter, исключения и diff.
Тройка и живое приложение не нужны. Этот режим действует для первоначальной основы
Hibiki: пока нет package.json и npm-команд, не создавать их ради зелёной проверки.
Изменения runtime-конфигурации работающего приложения требуют проверок её последствий.

## 2. Тройка после появления кода

Строго по порядку, после последних изменений:

1. `npm test` — итог тестов и файлов. Тестовая БД отделена от пользовательской.
2. `npm run build` — сборка приложения.
3. `npx tsc --noEmit` — типы всех пакетов.

Конкретные пути, setup и команды живых проверок бери из
[dev-env](../../../.ai/map/dev-env.md). Если их ещё нет, сначала определи
реальный способ проверки и зафиксируй, а не выдумывай существующий скрипт.

## 3. Живые поверхности

| Зона | Что подтвердить |
|---|---|
| UI/аккаунты | Настоящий браузер: вход двух пользователей, библиотека, редактор и изоляция |
| Медиа | Реальная загрузка audio/video, свойства, декодированный/слышимый звук, seek и HTTP Range |
| YouTube | Реальные single/playlist import, метаданные, повтор без дублей, частичный сбой и скачанный файл |
| Плейлисты | Вложенные списки/теги/items/исключения, обновление состава, explain, запрет циклов |
| Плеер | Play/pause/seek, очередь, shuffle/repeat, переход страниц и восстановление |
| Сворачивание | Отдельно local audio/video и YouTube: результат на целевом ПК, условия и ограничения |
| Задания | Прогресс, отмена и рестарт worker без потери/дублирования результата |
| MCP | Настоящий клиент: initialize, capabilities, импорт, jobs, playlist preview/explain/save |
| Права | Чужие items/playlists/jobs/files недоступны и из UI, и через MCP |
| Перенос | Export/import под другим аккаунтом и в чистой установке; файлы, хэши, настройки и граф ссылок |

Проверки выполняются по затронутым зонам и приёмке задачи. Для сквозного MVP
обязательны весь основной сценарий и перенос библиотеки. Моки не заменяют
реальные медиа, внешний источник, браузер или MCP в заявлении о живой проверке.

## 4. Запись и отчёт

В verify.md задачи: команды, числа, фактический результат, что наблюдал,
ограничения и «Что посмотреть руками». Доказательства —
`storage/verification/NN-slug/` вне git. Для начальной основы без приложения
результат допускается записать в `.ai/history.md`.

Пароли/токены не печатай и не коммить. Проверочные аккаунты/медиа — в storage,
не трогай чужие данные. Перед dev проверь порты и используй уже запущенную нужную
установку, если это подходит; не останавливай Asobiba/Douga.

Красное, пропущенное и нестабильное называй прямо. Пропуск фонового YouTube-playback
по согласованным границам MVP не выдавай за его успешную проверку.
